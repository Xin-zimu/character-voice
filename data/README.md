## 一句话

**同一批复幕，两种用途，两套门槛。**

- 当作「**剧情参考**」——这段对话里发生了什么 → 原文 + 上下文即可，**不要求**说话人标注
- 当作「**角色台词依据**」——这句是她说的 → 必须是 L2 人工核定

旧版本这里写的是「只有 L2 可以进入 prompt」。那句话与实现矛盾：检索层一直在把未标注的 L0 字幕作为剧情上下文注入。矛盾不在于实现错了，而在于用**单一门槛**去管两种用途。详见 [DEC-003](../docs/DECISIONS.md)。

## 分级

### L0 · 原始解析

| 路径 | 内容 | 条数 |
|---|---|---|
| `parsed/*.dialogue.jsonl` | 字幕逐条解析结果 | **13070** |

- ✅ 可以：做统计、做定位、建检索索引的原料；作为**剧情参考**注入 prompt（见下节「剧情参考」）

| 路径 | 内容 | 条数 |

| 路径 | 内容 |
|---|---|

| 路径 | 内容 | 条数 |
|---|---|---|
| `seed_nagato_lines.md` | 人工逐句核对上下文确认的长门台词。**只有台词表是核定结果**；里面那些统计与「硬约束」是当时的推论，已标为作废，不是运行规则（AUD-11，`test_37` 锁住） | 10 |

1. 说话人确定是长门，且经过人工或可信模型确认
2. 上下文完整，脱离语境后不产生歧义
3. 记录来源（集数 + 时间码），可回溯复核

## 两种用途的准入

### 用途 A · 剧情参考（注入 prompt）

**现在就在用。** `prompt_builder.py::render_hits()` 把检索命中的片段作为「原作记录」注入 system prompt。

| 要求 | 说明 |
|---|---|
| 分级 | L0 即可，不要求 L2 |
| 必备 | 原文 + 前后各 5 条上下文 + 集数与时间码 |
| 必须成立 | 片段属于**当前世界**（见「世界归属」） |
| 使用纪律 | 只当「这段对话里发生了什么」；不复述、不念原文、不说「第几集」 |
| 明确不做的事 | **不声称某句是长门说的**。字幕没有说话人，片段里超过一半是旁人台词 |

prompt 里的对应约束：「如果片段里是别人的台词，那是你听到或看到过的事」。

### 用途 B · 角色台词依据（few-shot / 评估 / 引用）

| 要求 | 说明 |
|---|---|
| 分级 | **必须 L2** |
| 必需 | 说话人经人工确认 + 来源时间码 |
| 附加纪律 | 即使是 L2，也**不直接抄原文当示例**——那会让模型学「念台词」而不是「对话」 |

## few-shot 不直接抄原文，而是手写

`personas/*.json` 的 `examples` **全部按角色规则手写**，没有一句从 L0/L1 抄来，每条带 `source`：

| source | 含义 |
|---|---|
| `handwritten` | 按规则手写，无原文对应 |
| `handwritten:xxx` | 手写，依据某条具体规则（如 `ability-limit`） |
| `wiki:xxx` | 依据 haruhi.fandom 描述的行为特征 |
| `seed:<集>@<时间码>` | 取自 L2 种子台词（目前 0 条） |
| `verified:<集>@<时间码>` | 与废弃候选池重合、但已人工核实确为长门原句 |

为什么手写：原文台词是**剧情对话**，答的是阿虚的问题，不答「帮我看这段代码」。few-shot 的作用是标定**说话密度和语气**，不是复现剧情；手写才能控制分布。

**代价也要认**：手写可能偏离真实语言习惯。所以定了一条纪律——**新增示例必须写 `source`，不允许凭印象编**。`scripts/check_persona.py` 会检查。

## 世界归属

`build_corpus.py` 给每条标 `world`（`normal` / `crash`），检索时按当前世界筛选。

当前实现：只按《消失》`0:38:13` 一刀切，切点之后全算 crash（主线 11496 / 崩溃 1574）。

**⚠️ 已知问题**：单一时间点不可靠。片尾 `2:41:10` 起 5 条对白出现在 `2:36:13` 之后约 298 秒的空档里，疑似已回到原世界，现在却被标成 crash。归属审计与区间表是 [BLK-001](../docs/STATUS.md) 的内容。

因此：**归属不可靠的片段，不得作为该世界的经历使用。** 宁可标 `unknown` 排除在检索外，也不要默认归到某一侧。

**判断污染看归属，不看关键词**：crash 世界里出现「春日」「朝比奈」是剧情内的正常讨论（实测 `凉宫春日` 10 处、`朝比奈` 42 处），那是她在谈论消失的春日，不是跨世界污染。

## 正确产出 L2 的路径

```
parsed (L0) → scenes (L1) → annotate.py 标注 → 人工复核 → labeled (L2)
```

**跳过任何一步都会污染下游。** 特别是「先按字面特征筛选再标注」这种省事的思路已经试过，失败（1118 条、精度 15%）。

教训：**中间产物必须有明确的准入门槛，否则它迟早会被当成素材用掉。**

## 禁止事项速查

- ❌ 把 L0/L1 当 few-shot 示例
- ❌ 声称某条未标注字幕是长门说的
- ❌ 使用 `_deprecated/candidates_heuristic/` 里的任何内容
- ❌ 把归属未定的片段当作某世界的经历
- ❌ 新增无 `source` 的示例
- ❌ 为省钱跳过人工复核就说某批是 L2
