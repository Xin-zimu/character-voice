# 长门有希 · 文字助手（YUKI.N&gt; 终端）

> 第 06 集 13:24，阿虚的显示器亮起来，屏幕上出现 `YUKI.N>能看到吗？`。
> 她不在这个房间里。信号是从另一个世界挤过来的。
>
> 这个项目做的就是这个界面。

一个和长门有希**持续相处**的文字聊天项目。你和一个在另一条世界线上的她，通过一块终端屏幕通讯。

不是通用助手，也不是酒馆式角色扮演。

## 跑起来

**本仓库不包含字幕语料**（版权原因）。克隆后需要自备字幕，否则检索为空——程序能跑，但不会有原作片段。

```powershell
cd character-voice
# 1. 把解析好的字幕放进 data/parsed/*.dialogue.jsonl（格式见 data/README.md）
py build_corpus.py         # 建索引
py server.py
```

没有语料也能启动：检索退化为「无原作片段」，她只凭人格卡回答。回归测试同样降级——依赖语料的用例会**跳过并说明原因**，前端与 HTTP 链路测试照常运行。

默认地址 **http://127.0.0.1:8766**。端口被占用会在后续 9 个端口内自动顺延，以启动输出的地址为准。

点右上角 ⚙ 填 API Key（DeepSeek / 阿里百炼 / 硅基流动 / 本地 Ollama 都行）。Key 只存在浏览器 localStorage，不落盘、不上报。

### 可选后端：用本机的 Qoder 账号

装了 `dsh-qoder-connect` 插件并且已登录的话，可以不开 API Key，直接用它的额度：

```powershell
node qoder_backend.mjs        # 另开一个窗口，保持运行
py server.py
```

网页会自动接上，不用去设置里选。

它和插件一样是**外挂件**：项目本身不依赖它，没装插件就用 ⚙ 里自己的 API Key。它把插件的 loopback 端点换成固定地址暴露出来，复用插件自己的凭证与签名逻辑。**依赖插件的内部构建产物**，插件升级后可能失效——失效时设置面板会直接显示原因，不会静默失败。详见 [DEC-009](docs/DECISIONS.md)。

> PowerShell 自选起始端口：先 `$env:PORT='8770'`，再 `py server.py`。
> 需要走系统代理时：`py server.py --use-env-proxy`。

## 当前可用功能

| 功能 | 说明 |
|---|---|
| 双世界切换 | 主线 / 崩溃两张人格卡，界面配色、打字节奏、对话记录各自独立 |
| 终端形式 | 每条回复带 `YUKI.N>` 前缀（协议添加），按 42ms / 68ms 逐字显示 |
| 原作检索 | 13070 条字幕建 BM25 索引，按话题检索并注入上下文 |
| 流式对话 | SSE 透传；中断保留已收到内容并标 `△ 流中断` |
| 记录持久化 | 每世界最多 200 条；服务端发送最近 12 轮历史 |
| 重说 | 单条重新生成，不必重开对话 |
| ▤ 资料终端 | 按集翻全量原文，高亮「长门/有希」被提到的行 |
| ◇ 校对 | 查看**这次实际发出去的 prompt**，不调用模型、不花钱 |

## 当前实现与产品方向不一致的地方（待调整）

以下三项**现在确实是这样**，但已被确认为要改的方向。看实现时不要以为这就是最终设计，改动进度见 [docs/STATUS.md](docs/STATUS.md)。

| 现状 | 产品方向 | 相关规则 |
|---|---|---|
| ⚠️ **禁止动作描写**：提示词写「屏幕上只有字」 | 改用小说式 `（）` 括号互动，允许纯动作回复 | [CHAT-007](docs/PRODUCT.md) |
| ⚠️ **校对面板不是上一轮**：`◇` 是拿当前输入重新组装，不是刚发出去那条的真实请求 | 分「下一次预览」与「上一轮实际发送」 | [CHAT-006](docs/PRODUCT.md) |

另外，字数统计仍**显示在主聊天区**（每条回复下方 + 底栏「本轮 N 字 · 平均 N 字/句」），按 [CHAT-006](docs/PRODUCT.md) 应移入调试面板。

> **已完成的两项**（2026-10-21）：
> - **字数上限已取消**。人格卡不再有 `max_chars`，前端与自检也不再判定超长——长回复不会因长度被标 `△`、截断或重写。
> - **跨世界已严格隔离**。检索只在当前世界内进行，另一世界的片段不注入、不标注、不暗示。

> **关于世界标签**：`◇` 面板里命中的片段带着当前的世界标签，但**这些标签本身未经审计**——它们按单一时间点切出来，不能当作归属正确的证据。见 [docs/STATUS.md](docs/STATUS.md) 的 BLK-001。

## 原作锚定

每句话发出去之前，服务端会：

1. 拿这句话去 13070 条原作台词里检索（BM25 + 近邻去重），**只在当前世界内检索**
2. 把命中的**完整对话上下文**（前后各 5 条）注进 system prompt
3. 让她把这些当记忆用——不复述、不念原文、不说「第几集」

**检索只做剧情锚定**：字幕没有说话人标注，所以只告诉她「这段对话里发生了什么」，不声称「这句是你说的」。准入要求的完整说明见 [data/README.md](data/README.md)。

**世界隔离**：另一世界的片段不会出现在 prompt 里——不注入、不标注、不给「你也许想起了什么」这类提示。这条是硬约束（[WORLD-001](docs/PRODUCT.md)、[DEC-002](docs/DECISIONS.md)）。

## 调参入口

人格全在 `personas/*.json`，改完刷新页面即生效，不用重启。

| 字段 | 作用 |
|---|---|
| `system_prompt` | 行为规则。只写可执行的规则，不写形容词 |
| `examples` | few-shot。**这比 prompt 更管用**——模型学的是示例的密度与长短 |
| `guard.banned_patterns` | 违例正则，实时标记 |
| `protocol.prefix` / `type_delay_ms` | 终端前缀与打字节奏 |
| `theme` | 配色，切换世界时整个界面会变 |

> `guard.max_chars_*` 与 `guard.tech_keywords` 已于 2026-10-21 删除（DEC-001）。`check_persona.py` 与 `test_08` 会在它们重新出现时报错。
> **所有 `examples` 都会进入 prompt**，代码里不再截断——示例太多会撑大请求，由人格卡自己控制数量。

世界线描述在 `prompt_builder.py` 的 `WORLD_PROMPT` 里，不在人格卡里——人格卡管「她是谁」，`WORLD_PROMPT` 管「她那一侧发生了什么」。

改完跑 `py scripts/check_persona.py` 自检。**改角色规则前先读 [AGENTS.md](AGENTS.md) 第四节**：规则散落在五处，漏一处回归必挂。
