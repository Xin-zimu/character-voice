## 一、必须先分清的四类证据

四者证明的事情不同，**不能互相顶替**。

| 证据类型 | 证明了什么 | 不能证明什么 |
|---|---|---|
| **A. 自动测试通过** | 代码行为符合断言；路径、边界、流式、隔离等工程正确性 | 角色像不像、说话自然不自然 |
| **B. 本地假上游通过** | 端到端链路（HTTP、SSE、存档）在真实服务端上跑得通 | 真实模型的任何表现 |
| **C. 真实模型试聊通过** | 在当前模型 + 温度下，人格与规则表现可接受 | 换个模型仍然成立 |
| **D. 你认可体验** | 产品方向成立 | 工程正确性 |

**现行状态（2026-10-23）**：A、B 持续覆盖；C 有 2026-10-21 的一次记录（`dfmodel` + 0.85，单一模型、单一温度，见 §五），覆盖 P1 与 WORLD-001，未覆盖 P2–P5；D 仍无记录。
所以「语料 13070 条」「39 项通过」这类结论只属于 A/B，**不能**当作角色表现的证据；一次 C 类试聊也不能当作人格已全面验证。

## 二、自动回归（证据 A + B）

每阶段结束都要跑完这四项，全绿才进下一阶段。测试不调用付费模型。

```powershell
py build_corpus.py            # 语料与归属
py scripts/check_persona.py   # 人格卡自检
node scripts/test_frontend.js # 前端 + HTTP 全链路
py scripts/test_backend.py    # 后端与检索
```

### 当前基线（2026-10-23 实测）

| 项 | 结果 |
|---|---|
| `build_corpus.py` | 13070 条 / 29 片源；normal 11496、crash 1574；切点 `0:38:13` |
| `check_persona.py` | 0 错误；示例长度分布 主线 2–60 字（中位 9）、崩溃 4–54 字（中位 18） |
| `test_frontend.js` | 39 项通过（P1 前为 37） |
| `test_backend.py` | 13 项通过（P1 前为 8；新增 `test_12`；桥运行时 `test_11` 跳过） |

P1 与隔离新增的断言：

- `max_chars_*` / `tech_keywords` 字段存在即失败（防回流）
- 200 字、400 字长回复在**前端与 Python 两个检测器**中都不产生任何违例
- 两张卡的全部示例都进入 prompt（此前 `[:14]` 会静默丢弃末尾示例）
- `test_05_cross_world_isolation`：旧标记（`〔…〕`、`【跨世界】`、`浮上来`）**不得出现**；`hits` 无另一世界条目；注入块的上下文行不含另一世界时间点
- `test_05b_retriever_filters_by_world`：检索硬过滤，且索引仍是 13070 条
- `/api/backends` 始终 200；桥不可用时 `/api/chat` 明确 503，不静默回退
- `test_12_persona_no_superseded_framing`：按 AUD-01/02/04 **逐项成对断言**——废止的说法不在（`用词越少越好`、`情绪恒定`、`作为助手处理…`、`不做安慰`、`直接给建议或直接说该做什么`），改写后的说法在（`情绪外露很少`、`一句能说完就不说两句`、`持续的通讯`、`【相处方式】`、`对方没有求助时`、`对方在问该怎么办时`）；并检查示例不再示范无条件给建议。删掉段落或把旧规则加回去都会红

### 现有测试覆盖了什么

- 历史截断边界（最近 12 轮、从 user 起、省略提示）
- 存档上限（每世界 200 条）与配额满不丢内存历史
- 两张人格卡的全部示例不触发 `△`
- 前端与 Python 自检逐例一致（含 emoji 的 UTF-16 长度、超长样本）
- 逐字播放节奏（主线 42ms / 崩溃 68ms）、前缀隐藏、跨 token 前缀、减少动态效果
- 流式中断的七种情形（正常、断流、无完成标记、上游报错、空响应、存档失败、双世界隔离）
- 静态路径越界、端口顺延、检索锚点、近邻去重
- 示例不截断（`test_09`）
- **跨世界预览**（当前断言**存在**跨世界片段——做隔离时要反向重写）

## 四、试聊记录规范

核心规则重申（CHAT-015-B）若进入实验，使用相同模型、温度和测试历史进行有／无重申的对照；记录角色与世界边界的具体违例和机械重复现象。只有提示词中出现了重申文字，不能判定防漂移有效。

每次 C 类验证都要留下可复查的记录（不入库密钥与私人聊天全文，只留摘录）：

| 字段 | 内容 |
|---|---|
| 日期 | YYYY-MM-DD |
| 模型 / 温度 | 例如 `deepseek-chat` / 0.85 |
| 世界 | normal / crash |
| 场景编号 | `V-*` |
| 轮数与摘录 | 关键轮次原文 |
| 命中片段 | 集数、时间码、世界归属 |
| 结论 | 通过 / 不通过 / 部分通过，附具体理由 |

试聊结论记在这里的「最近验证结果」，不必另开文档。
