## 一、必须先分清的四类证据

四者证明的事情不同，**不能互相顶替**。

| 证据类型 | 证明了什么 | 不能证明什么 |
|---|---|---|
| **A. 自动测试通过** | 代码行为符合断言；路径、边界、流式、隔离等工程正确性 | 角色像不像、说话自然不自然 |
| **B. 本地假上游通过** | 端到端链路（HTTP、SSE、存档）在真实服务端上跑得通 | 真实模型的任何表现 |
| **C. 真实模型试聊通过** | 在当前模型 + 温度下，人格与规则表现可接受 | 换个模型仍然成立 |
| **D. 你认可体验** | 产品方向成立 | 工程正确性 |

**现行状态（2026-10-24）**：A、B 持续覆盖；C 有 2026-10-21 的一次记录，2026-10-23 两世界 5 轮复测发现 L-01（后由 AUD-14 处理）；本轮用 `dfmodel` + 0.85 对 PEND-012／013 做 16 次有限前后对照，仍发现习惯编造 L-02（见 §五）。不能写成完整「C. 真实模型试聊通过」；D 仍无记录。P2–P5 的完整效果矩阵与完整 V-CHAR-02 前后对照仍未完成。
所以「语料 13070 条」「66 项通过」这类结论只属于 A/B，**不能**当作角色表现的证据；一次 C 类试聊也不能当作人格已全面验证。

> **2026-10-23 补一条更硬的边界**：A 类证据（自动测试通过）**也不能证明功能没 bug**。合入 ZIP 版本后，
> 七项全绿的状态下仍复现出 8 条真实缺陷（见 §五）。断言只覆盖写测试时想到的形状；
> 「测试没红」与「行为正确」是两件事。
>
> **同一条边界还咬了自己两次**：修这 8 条时，有两条新用例**本身是假断言**——
> R-01 的用例按 `ep_title`（「凉宫春日的消失（剧场版）」）去反查集名 `ep`（`消失`），
> 永远查不到，断言恒真；R-05 的用例自己调 `update_from_reply()`，把 `api_chat()` 里的接线删掉照样绿。
> 两条都是靠变异测试才暴露的：前者表现为「变异**没被拦住**」，后者表现为「变异**不生效**」。
>
> 所以现在的规矩是：**新用例必须先看到它红一次**，才允许它绿。写完就跑一遍是没用的——
> 一条永远为真的断言，跑一百遍也都是绿的。

脚本还会检查**变异是否真的生效**：`str.replace` 匹配不到时不会报错，变异变成空操作、测试自然全绿，脚本却打印「已拦住」——那是假证据。现在每次变异后比对文件内容，未变化就报「变异失效」并计入失败。`main()` 抛异常时以退出码 2 结束，不会把崩溃读成成功。

> M3 第一次跑出来是「未拦住」，但那不是测试的漏洞：变异只删了含「怎么办/该不该」的那一条，`帮我…` 也是求助，删完还剩示例——正确行为，自然全绿。现在变异函数直接复用测试的 `ASK_RE` 判定要删哪些，避免「变异没生效」被读成「测试没拦住」。这类误读会让项目凭空多出一条「缺口」。

> M12 反过来：**变异真的生效了，测试却没拦住**，是实打实的缺口。原因是当时只走 HTTP 测隔离，而接口层按世界分文件，每条记录自带 world 字段——把 `search()` 的过滤删掉，输出一模一样。补的 `test_13a` 直接对 `MemoryStore` 断言，并造出两种「真出问题」的形状：同名文件里混进另一世界的记录（目录拷错）、记录缺 `world` 字段（外部脚本改过）。加完 M12 才报红。

#### 追加说明（2026-10-23，P5）

> **M18 / M19 第一版「未拦住」，但都不是测试的漏洞，是变异写错了。** 这两条比 M3 更容易误判，所以逐条写清：
>
> - M18 用「（别摘眼镜）」当断言句。这里的「摘」既在否定词后面，也正是 `_GLASSES_OFF` 的模式本身；去掉豁免后仍然匹配不上，状态没变、测试全绿。真正的漏洞要换成否定词与动作词**分开**的句子才暴露——而这类句子当时**确实会改错状态**，是补这条变异时查出来的两个真 bug：
>   - `（有没有翻开书）` 被读成「翻开了」：正反问里的「没有」看着像否定，其实是在问。
>   - `（别把书合上）` 被读成「合上了」：否定词与动作词隔着一个宾语。
>   两处都已修，并各留一条回归（`test_scene.py::test_03a` / `test_03b`）。**修 bug 的线索来自变异，不是来自测试**——这说明当时的用例覆盖不到这两类句子。
> - M19 第一版让两个世界都指向同一个**新建**的 `Scene('normal')`。这样崩溃世界的默认值也变成了主线的默认值，而用例里两边被改成的值恰好一样，看不出差别。换成「崩溃世界复用主线**已存在**的那个对象」就红了。
>
> **M21 在改动判据后一度报「变异失效」**——这是脚本在正常工作：`str.replace` 的锚点随实现变了，变异成了空操作。脚本报的是「变异失效」而不是「已拦住」，两者分开计数，所以不会伪造保护证据。锚点更新后又补了 M25 覆盖新查出的「我在想活动室」误判。
>
> 区分「变异没生效」和「测试没拦住」的办法只有一个：改完变异先确认它会红一次，再看是哪条断言红的。M15 现在的期望项是「任一写入路径」而不是具体用例名，就是因为它的几条冗余路径会先红——**只有去掉冗余才能确认哪条断言在尽责**。

**独立复审（未参与实现的子 Agent）查出的四件事，全部已修并各留回归：**

1. **两端 `checkReply` 已经不等价**（最严重）：前端给字符画豁免了「分段」，Python 的 `simulate_check_reply` 没豁免。自检报「分段」、界面不报，而 `test_backend.py::test_30` 正是靠这个模拟器判定的——**当时没有任何用例比对这一条**，所以全绿也不说明它对。修：模拟器同步豁免，并把「图案带空行」与「普通空行分段」两条一起塞进逐例比对样本。补 M41。
2. **`check_art` 只查左边距、不查右边距**：左齐右不齐（`  ────` / `      ────`）照样返回 `[]`。修：加右边缘检查，阈值 3 格（差 1 格是图案自己的收尾，不该报），且**只在图案块内比**——第一版拿全部行当参照，结果把自己人格卡里的示例判歪了，这正是补检查时立刻暴露的。补 M44。
3. **空格被算进「符号」**：`   你好呀 /    今天很好` 四格缩进凑够「连续 3 个符号」，两行普通文字被判成字符画、整段换成保空白排版。缩进在模型回复里很常见（列表、引用、排版），不是边角情况。修：连续串必须含至少一个**图案字符**；双空格那条也要求至少一个图案字符。两端同步。补 M42 / M43。
4. **`art_blocks` 会把紧邻图案的文字行卷进图案块**（`句子。/ /// / /// / 句子。`→ 第二行被当图案）。评估后**保留现状**：那一行的内容确实只有符号，判成图案不违背「按内容排版」这条原则，而收紧（要求缩进一致）会让「居中的小图」整块失效。改写进 PEND-011 作为已知取舍。

另记两笔不构成当前缺陷但值得知道的：前端 `cellWidth` 用范围表、Python 用 `unicodedata`，在**未分配码位**上会有分叉（`Ⓚ` 一类）；`strip_prefix` 只剥一层首尾空行。两者都不在 `ART_CASES` 覆盖面内，先记在这里。

**M40 第一版「未拦住」**：DOM 结构断言看不出样式——结构全对，文字照样被压成一行。补了一条直接读样式表的断言才拦住。这类「结构对了、观感不对」的问题只能从样式层测，不能靠 DOM 树。
