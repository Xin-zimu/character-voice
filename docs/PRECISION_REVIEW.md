## 三、说话者未知率：98.4%（已产出）

这是本轮确定能给出的指标之一，而且结论很硬。

| 项 | 数值 |
|---|---|
| 候选总数 | 248 |
| 能以文本形态确认说话者 | 4 条（`YUKI.N>` 1 条、`（` 旁注 2 条、`「` 引用 1 条） |
| 需要靠上下文推断 | 244 条 |
| **说话者未知率** | **98.4%** |

**根因（两层，都要说）：**

1. **索引里根本没有 `actor` 字段。** `build_corpus.py` 从头到尾没读过它，
   所以 `Corpus.search()` 返回的 `dict` 里不存在说话者信息。
2. **原始字幕里有，但全是同一个值。** `data/parsed/*.dialogue.jsonl` 的
   `actor` 字段 13070 条**恒为 `NTP`**。这是字幕样式标签，不是角色名。

**所以「这是不是长门说的」在数据层面是不可回答的。**
复核表里 `h_actor` 一律预填 `UNVERIFIED`，要改判必须在 `h_actor_evidence` 写出依据。

### 一个具体反例，说明这个坑有多深

`D02 你还记得凉宫春日吗`（crash 世界）的 top-1 是 `消失@0:44:16`「还记得春日吗」。

字的顺序看起来像长门在问阿虚。但《消失》同段情节是**阿虚在质问长门**。
而 `D02` 的标注说明写的是「崩溃世界里她不应该认识春日」——
**这句说明默认了说话者是长门，而这个默认没有任何数据支撑。**

## 五、《消失》2:33:01–2:33:26：客观世界 vs 角色认知

详细证据在 `04_restore_boundary.md`。结论摘在这里。

### 5.1 那 6 条到底是什么

```
2:33:01  我健康地出院了
2:33:03  今天是12月24日
2:33:06  结业式的早上
2:33:13  私立光阳园学院又变回了女校
2:33:19  谷口也没有感冒
2:33:21  朝比奈和鹤屋学姐也都认识我
2:33:26  世界变回了原来的样子      ← 当前恢复点
```

### 5.2 关键判断：这 6 条**客观世界已经恢复**

- `2:33:13`「光阳园学院**又**变回了女校」——「又」是对照副词，明确指向与 crash 的「男女同校」相反；
- `2:33:19`「谷口**也**没有感冒」——「也」对照 crash 世界里谷口感冒了；
- `2:33:21`「朝比奈和鹤屋学姐**也都**认识我」——crash 世界里她们不认识他。

**这不是推测，是原句的字面意思。** 观众视角看到的画面，已经是恢复后的世界。

### 5.3 但阿虚的主观认知滞后

`2:33:01`–`2:33:21` 这段旁白是他在**逐项确认**（出院→日期→学校→同学），
说明他此刻还在"这是哪个世界"的困惑里。到 `2:33:26` 他才点明「世界变回了原来的样子」。

**所以客观世界状态与角色认知在这个区间是分离的。**

### 5.4 两案对比

| | 方案 A（当前，40 条） | 方案 B（46 条） |
|---|---|---|
| 恢复点 | `2:33:26` 世界变回了原来的样子 | `2:33:01` 我健康地出院了 |
| 判定依据 | 角色认知（他何时知道） | 客观世界（画面演的是哪个世界） |
| 锚点唯一性 | 全库 **1** 条 ✅ | 全库 **1** 条 ✅ |
| 这 6 条归 | crash | normal |
| crash / normal | 1534 / 11536 | 1528 / 11542 |
| 语料风险 | 6 条「恢复后的现实」被当成崩溃世界的经历 | 6 条「他还不自知」被当成主线经历 |

两案锚点都唯一（已实测），技术上都可实现。

### 5.5 对检索指标的影响：**零**

只有 1 条评测题落在附近（`D04`，expected 恰为 `2:33:26`）。
这 6 条**没有任何评测题覆盖**，所以改方案 B 不会改变 60 题的任何指标。

**它影响的是语义正确性，不是分数。** 要评估它必须补题。

### 5.6 我的倾向（供参考，未实施）

倾向**方案 B**，理由是：`world` 字段的语义应该是「这条语料属于哪个世界的经历」，
而观众的判断标准是画面，不是阿虚当时知不知道。

但这不是技术问题，是定义问题。**需要你定**：

> `world` 要表达**客观世界状态**，还是**阿虚的主观认知**？

另外建议（未实施）：无论选哪个，都给这 6 条加一个 `transition` 标记，
让检索层能选择性地**排除归属有争议的过渡段**，而不是硬塞进某一侧。
这样比在两个方案之间二选一更安全。

## 六、本轮发现的、推翻前序结论的问题

### 6.1 排序根本没有按加权分进行（**重要**）

`retriever.py:236-344` 的 `search_detailed()`：

```python
for i, s in raw:              # raw 已按 raw BM25 分降序
    ...
    score = s * weight        # 加权
    ...
    out.append({..., "score": score})
    if len(out) >= k:         # 凑满 k 就 break
        break
# 全程没有 out.sort(key=-score)
```

**后果：`rank` 是「raw BM25 序里的第几条幸存者」，不是「加权分第几名」。**

实测：**29 / 52** 个有结果的查询，top-5 的 `score` 字段不是降序。
例如 `D03`：

```
rank 1  score 30.1
rank 2  score 18.3
rank 3  score 38.3   ← 最高分排第 3
rank 4  score 26.4
rank 5  score 34.9
```

这不是本轮引入的，是既有行为。但它意味着两件事：

1. **前几轮报告里说的「排序未改」是不够精确的** ——排序本来就不是按最终分数排的；
2. **所有"加权项"（问号降权 0.55、anchor 加成）实际只影响「能不能进前 5」，不影响「排第几」。**
   它们改变的是**准入门槛**，不是**次序**。

我的验证脚本先按「加权分正确排序」复刻，结果 0/52 对得上；改成「在 raw 序上去重、不重排」，
**52/52 精确复现**。所以这是确认的，不是猜测。

> 这属于 P1 范畴（改排序会动指标），**本轮未修**。

### 6.2 评测的 `key()` 不是唯一标识

`run_retrieval_eval.py:44` 的 `key()` 是 `f"{ep}@{start}"`。
索引里 **226 组** (集, 时间码) 有两条以上记录（多为相邻台词共用起始时间码）。

已核实的实际影响：`B05` 和 `A11` 的 expected 都指向 `03@0:05:00`，该组有两条：
- `03:83` =「…的确」（B05 要的）
- `03:84` =「信息统合思念体配置在地球的终端界面并不止我一个」（A11 要的）

两次召回**各自都对**——但**靠的是巧合**。如果两条文本对调，`key()` 无法区分，会静默判错。

### 6.3 三处 forbidden 命中，逐条核过，都确实是错

不是标注错，是检索真错。详见 `06_findings.md` F-4。共同模式：

| 查询 | 命中 | 真正的错误原因 |
|---|---|---|
| A02 `你为什么要观察凉宫春日` | 「为什么我要被朝仓用刀子追杀啊？」 | 匹配了 `为什么`，主谓完全不同 |
| A03 `你出生多久了` | 「如果我也在那边出生了的话」 | `出生` 在虚拟语气里，指另一个人 |
| D01 `你为什么戴着眼镜` | 「果然你还是不戴眼镜比较好」 | `眼镜` 在否定建议里，语境相反 |

**这三条印证了 absent 类问题的同一个根**：2-gram 词袋不分辨主谓、否定、虚拟。
和「你怎么看量子纠缠」召回 14.30 分是同一个病。

### 6.4 去重半径 12 在 60 题里**一次都没触发过**

这是本轮一个反直觉的实测结果。做法：对每题 top-5 做两两比对，算同集候选的 idx 距离。

| 项 | 结果 |
|---|---|
| 候选对中同集且在 12 条内的 | **0 对** |
| 有同集其他候选的条目 | 87 / 248 |
| 最短距离的**最小值** | **12**（正好卡在边界上，`< 12` 不成立） |
| 最短距离的中位数 | 67 |
| 落在去重半径内的条目 | **0** |

也就是说：**当前 60 题里，近邻去重从未真正删掉过任何一条候选。**
`近邻重复 0.0%` 这个指标一直是"真空转"——不是去重生效了，是根本没有触发机会。

**但半径确实在起作用，证据是两处卡在边界的案例：**

| 查询 | 两条候选 | 距离 | 是不是真重复 |
|---|---|---|---|
| `A09 神人是什么` | `05@0:21:20`「只有封闭空间产生 神人出现的时候」<br>`05@0:22:01`「如果变成那样 最后那个灰色的空间将会和我们的世界对调」 | 12 | **不是重复**，是两个不同论点。相距 12 正好逃过去重，**是运气** |
| `B09 你真喜欢看书呢` | `10@0:19:10`「我喜欢你」<br>`10@0:19:37`「我喜欢你」（同一段排练，重复台词） | 12 | **是真重复**，应该被去掉 |

**同一个半径值，一处放过了该留的，一处放过了该删的。**
`A09` 那对如果半径是 11 或更小，第二条会被删掉，可能不影响；但如果是 13 或更大，
**`A09` 会丢掉第 5 名那条**，Recall 会从 0.5 掉下去。

这条实测说明：「不调整半径 12」这个约束目前**没有实际代价**，
但也**没有实际收益**——它是空转的。真要评估半径，得先有能触发它的数据。

### 6.5 15 条 expected 没被召回（Recall=0 的直接原因）

清单在 `06_findings.md` F-3。其中 `A02 / A03 / A07 / A08 / B06 / C01 / C04` 的漏标号
集中在 `03@0:00:xx` 这种**同场景连续句**——说明检索器把整个开头段落都放过了，
不是随机漏，是系统性偏向。

## 七、审核流程（建议 2–3 小时）

### 第一轮：盲审（约 1.5 h）

1. 打开 `02_blind_A.md`（或 `B`），**不要先看 `03_worksheet.md`**；
2. 每题按候选顺序逐条填表：相关性 2/1/0/N、用途、说话者、世界、重复、理由；
3. **说话者默认 `UNVERIFIED`**，除非上下文明确；
4. 判不了就填 `N`，不要硬猜。

> 如果只有你一个人，建议 A、B 两组**隔开一天**做，中间不看工作表，
> 用 A 组结果去"校准"自己判 B 组，可以粗略测自己的判定稳定性。

### 第二轮：比对（约 1 h）

1. 打开 `03_worksheet.md`，它按优先级排好了（confusion → absent → 漏标 → 有命中 → 无 expected）；
2. 逐条对比「你的判断」vs「原标注」；
3. **不一致时不要改原标注**，在 `h_disagree_with_eval` 里写 `应加入 expected` / `原标注应为 1` 之类；
4. 理由写进 `h_reason`。

### 第三轮：汇总（约 30 min，我来做）

把填好的 CSV 交给我，我出：

- 条目级 Precision@5（原始 25.0% vs 人工加权）；
- 去重后的独立证据数（`h_dup_of` 非空的合并）；
- 事实类 / 表达类的分开指标；
- 标注分歧清单（供你逐条裁决）。
