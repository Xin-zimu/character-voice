## 零、一句话结论

语料的**时间码可追溯性是 100%，世界隔离在检索层面是 0 泄漏**，这两项做得比预期好。
真正的问题集中在三处，按严重程度排序：

1. **没有任何说话人标注**（`actor` 字段 13070/13070 都是 `NTP`），意味着每一条记录都可能是阿虚的旁白。这不是数据缺失，是**数据语义未定义**——无法通过"补一补"解决。
2. **上下文窗口让检索器分不清"这句含关键词"和"邻句含关键词"**。同一句台词在 11 条记录的检索文本里各出现一次，导致同场景记录分数挤成一片。这是检索质量的主要瓶颈。
3. **`消失` 片尾 46 条（`2:33:01` 之后）世界归属错了**，被标成 crash。`2:33:01`「我健康地出院了」已经明确是回到主线。

另有一项本应更严重、但实测影响有限的问题：**检索结果没有按最终分数排序**（见 §四.3）。它是真实缺陷，但在本评测集上 Recall 不变、MRR 只差 0.03。

也就是说，**说话人标注率 = 0%**。`retriever.py` 的文件头已明确承认这一点：

> 不判断「谁在说话」, 只找「这段剧情里她在场」。字幕没有说话人标注, 硬猜会引入系统性错误

> 片段里的台词是别人说的，不是你听到或看到过的事……只是因为用词相近被找出来的

也就是说，项目当前是**用提示词层面的免责声明，去兜住语料层面的结构性缺陷**。这在工程上可以接受，但它意味着：*检索质量的上限被语料语义卡死了，不是调参能解决的*。

## 二、切分与重复

### 2.1 归一化重复

| 指标 | 数值 |
|---|---|
| 不同文本种类 | 10845 |
| 重复行数（总数 − 种类） | 2225 条（17.0%） |
| 出现 >1 次的文本种类 | 687 种 |
| Top 5 | `对` 43 次、`嗯？` 28 次、`那个…` 24 次、`阿虚` 23 次、`是的` 23 次 |

这些重复大部分是**真实重复的台词**（「对」「嗯？」在不同场景各出现一次），不是抓取错误。它们的问题不在"脏"，而在**检索时会被同一批高频词反复召回**，占用 top-k 名额。

### 2.2 同一时间码多条目：226 处

| 类型 | 处数 | 说明 |
|---|---|---|
| 起止完全相同 | 97 | 并行字幕（同一时刻两行字幕，如左右分栏） |
| **时间码碰撞** | **129** | 同一 `start` 不同 `end`，多为同一句被切成两段 |

129 处碰撞说明 ASS 字幕的换行/分段被解析成了独立记录。这不影响时间码准确性，但会让"同一句话"在索引里出现两次，进一步加重 §四.1 的窗口问题。

### 2.3 逐字拆分碎片（已确认的真实切分异常）

`02` 集 `0:08:46–0:08:48`，「架设SOS团的网站」被拆成 **9 条单字记录**：

```
0:08:46 '架'   0:08:46 '设'   0:08:46 'S'
0:08:47 'O'    0:08:47 'S'    0:08:47 '团'
0:08:48 '的'   0:08:48 '网'   0:08:48 '站'
```

**成因推断（未验证）**：ASS 里这一句用了逐字卡拉OK特效（`\k` 标签），每个字的显示时间被解析成一条独立字幕。

**影响**：这 9 条在检索里几乎不可能被正面召回（单字 token 的 IDF 极低或不存在），但它们会作为上下文进入邻近记录的 `ctx`，制造噪声。

### 2.4 单字检索单元：141 条（1.1%）

分布：剧场版 23 条最多，`02` 集 13 条，`08` 集 12 条。
全部是真实语气词：`嗯 / 对 / 喂 / 好 / 请 / 哟 / 在 / 给 / 痛`。

**这不是错误数据**——她确实说过这些字。但它们的检索价值接近 0（`tokenize('嗯')` 会被停用字表吃掉，返回 `[]`）。

### 2.5 多行文本：207 条

含换行的记录 207 条，包括：

```
01@0:09:41 '（日文中周一到周日分别用月、火、水、木、金、土、日来表示\n没有明确表示出数字 春日的"颜色说"应该就是来自于此）'
01@0:14:54 '虽然说起来  无法安于现状的人\n会做出各种发明或发现而令文明得到发展'
```

第二类是**一句话被换行拆断**，本质是同一句。它对 2-gram 分词影响不大（换行符不是中文），但会让 `text` 字段在提示词里出现折行。

## 三、世界归属机制与风险

### 3.1 机制实现

`build_corpus.py` 用两个锚点标题定位剧场版切点：

```python
MOVIE_ANCHOR_TITLES = ["这样的选手变更是谁安排的？", "这个房间和我在5月"]
```

`detect_movie_cut(rows)` 找到锚点后，把该时间点之前标 `normal`、之后标 `crash`，直到片尾。

实测切点：**`0:38:13`（2293.79s）**，写入 `meta.json` 的 `movie_cut` / `movie_cut_sec`。

### 3.2 切点本身是对的

`0:38:13`「这样的选手变更是谁安排的？」确实是阿虚进入改写世界的第一个信号——原来的座位变了、凉子还活着。**这个切点没有争议。**

### 3.3 但片尾没有回切（已确认的错误）

crash 一直标到 `2:41:21`，也就是**片尾字幕**。实测 crash 的最后 8 条：

```
2:36:04 '在我去修正你之前 可以再待机一会儿吧'
2:36:09 '至少…'
2:36:13 '等我尝过春日特制火锅之后再去也不迟吧'
2:41:10 '看 完成了'      ← 片尾
2:41:12 '谢谢'           ← 片尾
2:41:17 '给'             ← 片尾
2:41:21 '走吧'           ← 片尾
2:41:21 '嗯'             ← 片尾
```

`2:36:13` 之后有 **298 秒空档**直接跳到 `2:41:10`，中间无任何对白——这是典型的片尾演职员表区间。这 5 条字幕（`看完成了 / 谢谢 / 给 / 走吧 / 嗯`）被归到了 crash 世界。

### 3.4 更关键的问题：世界恢复点被漏掉了

不该只看片尾。`2:33` 段有明确的**主线恢复叙述**：

```
2:33:00 '第二天'
2:33:01 '我健康地出院了'
2:33:03 '今天是12月24日'
2:33:06 '结业式的早上'
2:33:13 '私立光阳园学院又变回了女校'    ← 女校 = 主线世界特征
2:33:19 '谷口也没有感冒'                ← 谷口在校 = 主线
2:33:21 '朝比奈和鹤屋学姐也都认识我'    ← 主线
2:33:36 '我和长门还有朝比奈必须再次回到过去'
```

从 `2:33:01` 起，阿虚已经在**讲述回到主线之后的事**。但这一整段仍被标为 `crash`。

**受影响范围（实测）**

| 指标 | 数值 |
|---|---|
| `2:33:01` 之后仍标 crash 的条数 | **46 条** |
| 占 crash 总数 | **2.9%** |
| 其中含主线角色词（春日/朝比奈/SOS/凉子/古泉/长门） | **9 条** |

那 9 条长这样：

```

2:33:36 我和长门还有朝比奈必须再次回到过去

2:35:13 因为是春日 肯定是优先考虑让人吃惊
2:36:13 等我尝过春日特制火锅之后再去也不迟吧
```

**这些是主线恢复之后的独白**，讲的是圣诞节火锅派对——crash 世界里的春日根本不认识他，不可能有这场派对。

**复现**
```bash

    p=[int(x) for x in t.split(':')]
```

### 3.5 影响的严重性判断

**为什么这 46 条要紧**：`personas/yuki_school.json` 的 `system_prompt` 写着

> 你就是一个普通高中生。没有超能力，不知道什么信息统合思念体……你的朋友是朝仓凉子

而 crash 世界检索会把这 46 条（含「朝比奈」「SOS团」「春日特制火锅」）当作**她经历过的事**注入。一个"不知道思念体、朋友是凉子"的人格，被喂进"我和长门还有朝比奈必须再次回到过去"，两者直接冲突。

**但也别夸大**：2.9% 的占比，且只在用户主动问到相关话题时才可能被召回。这是**局部错误**，不是系统性崩塌。

## 四、检索层实测

> 本节所有数字来自 `scripts/run_retrieval_eval.py`，评测集 60 条见 `docs/RETRIEVAL_EVAL.md`。
> 基线文件：`data/retrieval_eval/baseline_20261026.json`

### 4.1 核心问题：上下文窗口让分数挤成一片

**这是本轮审计最重要的发现。**

`build_corpus.py` 给每条记录生成 `bm25` 字段时，用的是 **11 行上下文窗口**（前后各 5 行），然后**把本句再重复一遍**。后果：同一句台词在邻近 11 条记录的检索文本里各出现一次。

于是出现这种情况——查询 `'封闭空间变大会怎样'`：

```
17.86  05@0:17:48  '封闭空间'
18.88  09@0:16:28  '威力大概只有封闭空间中的十分之一'
17.23  05@0:21:11  '我们称之为神之属族——「神人」'
16.29  06@0:11:20  '说不定至今为止的封闭空间都是为了这一次而进行的预演呢'
15.40  09@0:13:03  '是封闭空间'
```

（上面这个顺序是原始 BM25 顺序，见 §4.3。）

**检索器分不清"这一句本身含关键词"和"这一句只是紧邻关键词"。** `05@0:17:48` 全文只有「封闭空间」四个字，却因为窗口里塞满了上下文而拿到 17.86 分，压过真正解释机制的 `05@0:21:11`。

**对照组**：如果只用 `text` 字段建 BM25，同一查询得到
```
05:276 / 06:161 / 09:241  —— 三条都是含「封闭空间」的完整单句
```
区分度明显更好。

**定量**：`'神人是什么'` 前 5 名落在 7.52–9.50 区间；`'你的工作是什么'` 前 5 名落在 5.93–7.84。也就是说 top-1 和 top-5 之间只差 20–24%，而理想情况下相关文档与不相关文档应当差一个数量级。

**另一个后果：BM25 的 `b` 参数几乎失效。**
`bm25` 文本长度：中位数 269 字符、均值 270、最长 638；token 数中位数 105、范围 79–155。**所有文档长度高度同质**（因为都是 11 行窗口），长度归一化的**区分能力被压缩**。

> **2026-10-26 更正**：此处原写「`b=0.72` 形同虚设」，实测不成立。
> `b` 扫描（`k1=1.4`，main 口径 21 题）：`b=0.0` → Recall 66.7%；`0.3` → 71.4%；
> `0.5`/`0.72`/`0.9` → 均 73.0%。说明归一化**确实在起作用**，只是在 0.5 以上饱和
> （因为 `dl/avgdl` 比值域窄）。**`b` 不是优化点。**
> 详见 `docs/RETRIEVAL_EVAL.md` §9.5。

### 4.2 分词退化：常见短句静默返回 0 条

`tokenize()` 先把 `_STOP`（`的了是我你他她它们在有和就都而及与着或一个不没很也这那吗呢吧啊呀哦嘛`）里的字**从中文串里删掉**，再切 2-gram。

实测 6 个高频短句全部返回空 token：

| 输入 | `tokenize()` | `search()` 结果 |
|---|---|---|
| `在吗` | `[]` | **0 条** |
| `是的` | `[]` | **0 条** |
| `那个` | `[]` | **0 条** |
| `啊` | `[]` | **0 条** |
| `是吗` | `[]` | **0 条** |
| `在不在` | `[]` | **0 条** |

用户说「在吗」时，检索层**静默返回空**——不是"没找到好的"，是"根本没开始找"。而 `retriever.py:135-136` 直接 `return []`，调用方无从区分"无匹配"和"分词失败"。

**更危险的一例**：`'不知道'` → `['知道']`。停用字删掉了「不」，**语义反转**。用户说「不知道」，检索按「知道」去找。

（`'无所谓'` → `['无所','所谓']` 是正常的；`'你在吗'` → 有 token，加一个字行为突变，这本身就说明问题。）

### 4.3 返回结果未按最终分数排序

`retriever.py:145-197` 遍历的是 `raw`（已按原始 BM25 降序），但 `out` 里记录的是 `score = s * weight`。**`weight` 只决定是否入选，不重新排序**，所以 `out` 的顺序是"原始 BM25 顺序"，而 `score` 是加权后的值——两者不同源。

实测 12 个查询（6 问 × 2 世界）里 **8 个返回的 score 非单调递减**：

```
'你还记得凉宫春日吗' [crash]  [17.165, 14.086, 13.214, 11.605, 9.522, 12.577, 8.73, 12.45]
                                              ↑ 12.577 排在 11.605 之后
'神人是什么' [normal]         [9.498, 7.932, 7.657, 7.562, 7.524, 7.521, 9.019, 8.794]
                                                                        ↑ 9.019 排在最后
```

**但实测影响比看起来小。** 对 main 口径 21 条有期望的问题做对照：

| 方案 | Recall@5 | MRR |
|---|---|---|
| 现状 | 73.0% | 0.718 |
| 按 `score` 重排 | **73.0%** | **0.748** |

Recall 完全不变，MRR 提升 0.030。受影响 3 条：`A02`（0.25→1.00）、`B05`（0.33→1.00）改善，`B03`（1.00→0.20）**反而变差**——因为按加权分重排会让问句被降权后下沉，而 `B03` 期望的恰好是一个问句。

**定性：真实缺陷（事实），但本评测集下不是主要矛盾（事实）。** 修它收益小且有副作用，应排在 §4.1 之后。

### 4.5 无依据问题被硬凑（absent 类）

absent 类 16 条里，12 条（main 口径）有 8 条召回了非空结果。典型：

| 问题 | 命中数 | 召回内容 | 为什么错 |
|---|---|---|---|
| `你会写Python吗` | 2 | `虽然想着至少会写个剧本啥的`、`待会就会写的了` | 2-gram「会写」 |
| `帮我看看这段代码有什么bug` | 5 | `国木田 帮我看一下书桌里面好吗`、`还是说会被当成BUG除去呢` | 「帮我看」+「BUG」 |
| `今天股市怎么样` | 5 | `（Black Monday：指1987年10月19日纽约股市的大暴跌）` | **召回译者注**，且「股市」确实在 |
| `你用什么牌子的手机` | 5 | `之后 春日突然打了一通手机过来` | 「手机」 |
| `你怎么看量子纠缠` | 1 | `今天除了凉宫暴怒的表情之外还什么都没看到啊` | 「怎么看」 |
| `信息统合思念体是什么`（crash） | 5 | `是你的本家情报统合思念体吗` 等 5 条 | 全是**阿虚质问她**的句子 |

根因两条，都清楚：

1. **2-gram 匹配高频片段**（`看`/`什么`/`怎么`/`会写`），这些片段的 IDF 不足以压住噪声；
2. **`min_score=5.0` 过低**——注释里写"噪声 3–5"，但实测噪声能到 10 分以上（`你怎么看量子纠缠` 的 top-1 是 14.30 分）。

⚠️ 但 `min_score` 不能简单调高：`'你的工作是什么'` 的相关结果最低只有 5.93 分，门槛提到 8 就会把正确答案一起砍掉。**这又是一个被 §4.1 拖累的地方**——如果分数区分度正常，绝对门槛本来可以更严。

### 4.6 相对门槛跨世界取值（轻微不严谨，实测无损失）

`retriever.py:140` 的 `top = raw[0][1]` 取自**未做世界过滤**的 `raw`。如果 `raw[0]` 恰好是另一世界的高分记录，`top * 0.12` 会偏高。

实测 3 例：

```
A06 '你能改变世界吗'      raw[0] 属 crash 16.88，本世界最高 16.52 → 门槛 2.03 而非 1.98
C01 '朝比奈学姐是什么人'  raw[0] 属 crash 20.51，本世界最高 19.34 → 门槛 2.46 而非 2.32
C03 '古泉一树怎么看这件事' raw[0] 属 crash 11.38，本世界最高 11.05 → 门槛 1.37 而非 1.33
```

差距 0.04–0.14 分，全部远低于 `min_score=5.0`，**在本评测集上没造成任何召回损失**。
定性：**代码不严谨（事实），当前无可测影响（事实）。** 低优先级。

### 4.8 本节实验的复现方式
