## PEND-008 · 记忆从哪里来：手动记还是自动抽取

- 阻塞级别：**硬**（产品选择，未确认前不实现）
- 背景：CHAT-016 要求「从对话里积累共同经历」，但没有说**由谁判断什么值得记**。目前实现只接受用户在 `◈` 面板里手动写下的条目；对话本身不产生记忆。
- 三种做法与代价：
  1. **只手动**（当前）：可控、不会记错，但用户要自己动手，多数人不会用，长期记忆形同虚设。
  2. **每轮都存原文**：简单，但等于把聊天记录换个地方放，检索时噪声极大，且与「共同经历」的定义不符（大部分对话不值得记）。
  3. **让模型自己决定抽什么**：最像真记忆，但**会记错、会自己编事实**，而且每一次抽取都是一次额外调用（有费用）。
- 当前默认：**停在做法 1**。理由是做法 3 的「编事实」风险直接撞上 CHAT-016 的「记录里没有的事就是没发生」，要先用真实模型测出抽取的准确率才敢开。如果你选做法 3，还需要你定：抽取用什么模型（是否允许额外费用）、用户能否看到并拒绝每条自动记忆（我建议能）。

## PEND-010 · 字符画的字体：没有任何已装字体能让图案真正对齐

- 阻塞级别：硬（直接决定「字符画能不能看」）
- 背景：CHAT-017 阶段 A 做显示层时，用真实 Chromium 量了页面实际用的等宽字体。数据如下（`font-size: 14.5px`）：

| 字符 | 实测宽度 | 按「ASCII 1 格」应有的宽度 |
|---|---|---|
| `a` / `│` / `─` / `┌` / 空格 | 8.7px | 8.7px ✅ |
| `雨`（汉字） | 14.5px | 17.4px ❌ **比例是 1.66，不是 2** |
| `⣿`（盲文） | 10.6px | 8.7px ❌ 跟哪一格都不齐 |

逐字体测过本机全部等宽字体：只有 `Noto Sans Mono CJK SC` 的汉字:ASCII 是 2，但它的 `│`/`┌`（制表符）走全角 14.5px——**没有任何一个已装字同时满足「ASCII 1 格 + 汉字 2 格 + 制表符 1 格」**。`document.fonts` 为空，说明页面没引 web font。

- 实际观感：`┌──────┐` 会被拉成一个竖长方体，盲文点阵会挤成一小团（截图见本轮交付说明）。程序层面的对齐判据（`check_art`）是对的，字体的锅不是判据的锅。
- 三种做法与代价：
  1. **图案只用纯 ASCII**（`/\_/\`、`o.o` 这类）：现在就能对齐，代价是画不出细一点的形状，也画不了盲文点阵。
  2. **引一个 web font**（如带盲文的等宽字体）：观感最好，但**破坏「零依赖、单文件 HTML」**这条一直守着的约束——需要你确认，还要考虑断网时回退。
  3. **接受 1.66，在提示词里限定画法**：不让画方块框和盲文，只允许短行 ASCII 图案。改提示词即可，代价是表达范围被压窄。
- 当前默认：**停在 3 的一半**——提示词里已经写了「一行里只用等宽字符，靠空格对齐；不要用 emoji、不要用中文标点排图」「图案要小」，但**没有禁止制表符和盲文**（因为那等于替你选做法 1）。同时 `check_art` 会把「盲文/块元素与汉字混排」当作 △ 提示出来，不假装没这回事。
- 需要你给：选 1 / 2 / 3 中的哪一条。选 2 需要你明确允许引入外部字体文件。

## PEND-011 · 图案与文字同条时的分块取舍

- 阻塞级别：软
- 背景：一条回复常常是「一句话 + 一张小图 + 一句话」。整条按 `pre` 排版会把文字行也压成一行（实测句号被挤到下一行单独出现），所以改成了**按块排版**：图案块 `pre`，文字块正常折行（`textart.art_blocks`）。
- 分块的判定是「连续两行都像图案才算一块」。副作用：**表格里写字的行**（`│ ok │`）不算图案行，所以一行表格会一半保空白、一半折行。
- 当前默认：宁可少判，也不把文字行当图案。理由：文字被压成一行是**每次都会发生**的难看，表格歪是**偶尔**的难看。
- 如果你更在意表格：可以改成「一旦起块，直到空行/文字行超过 N 字才结束」，代价是文字行偶尔会被卷进图案块。改动只在 `art_blocks` 与 `artBlocks` 两个函数。

**复审提出的第二种情形（我评估后保留现状，记在这里供你推翻）**：紧邻图案、内容只有符号的文字行会被卷进图案块。比如

```
句子。
///
///
句子。
```

第二、三行会被当成图案块。看起来像误判，但内部评估的结论是**保留**：

- 那两行的内容确实只有符号，按「看内容排版」这条原则，判成图案不算错；
- 要收紧只能加「缩进必须一致」或「符号占比」这类条件，而「居中的小图」两边缩进天然不同（例如 `  /\_/\` 与 `   > ^ <`），一加就整块失效；
- 真正的代价只是那两行少折行，最坏情况是出现横向滚动条，不会丢内容。

如果你认为这种情况比「居中图案失效」更不能接受，可以改成按「连续符号行数 ≥ 3 才起块」——代价是小图（常见只有 2 行）不再保空白。

## PEND-012 · AUD-05 的两句缺依据表述：删掉还是留

- 阻塞级别：软
- 位置：`personas/yuki.json` / `system_prompt` 的【具体行为规则】
- 原句（两条，逐字）：

  > `- 对事实、数据、逻辑的判断准确。对人的动机和情绪的推断常出错，因为信息不完整。这时要说明是推测，不要装作确定。`
  > `- 自我评价偏低。被夸奖时不接受也不反驳，直接跳过。`

- 核查结果（在 13070 条语料里检索，normal 11496 / crash 1574）：

| 关键词 | 命中 | 说明 |
|---|---|---|
| `碰壁` / `高估` / `低看` / `判断错` / `错估` / `看不透` / `估错` / `猜错` / `不懂人心` / `说不准` | 0 | 没有一处直接支持“推断常出错”的自我陈述 |
| `推测` | 1 | `虽然只是推测 但这里恐怕也很快就会变成平常的世界了吧`，是剧情推测，不是自我评价 |
| `无法理解` | 5 | 全部是**别人**说她（`她就是个令人无法理解的怪人`／`你也无法理解`），不是她自述 |
| `误会` | 3 | 均为他人视角，无一条是她承认自己判断错 |
| `对自己` / `不高` / `很差` / `不擅长` | 0 | 两张卡里也没有别的自我贬低句 |

- 我的判断（不是结论，只是供你参考）：
  - 前半句「对人的动机和情绪的推断常出错，因为信息不完整」**不只是缺依据，还可能是反的**。原作里她的问题不是“推不准”，而是“能读出结论但说不清理由”。更接近的写法是「能看出不对劲，但说不太清为什么」——这需要真实试聊（PEND-001）才能验证，我不擅自改。
  - 后半句「这时要说明是推测，不要装作确定」**单独看是好事**，它防的是装懂，与 `不确定就说「不确定」` 那条同向。缺依据的只是“推断常出错”这个前提。
  - 「自我评价偏低。被夸奖时不接受也不反驳，直接跳过」**两句都没找到依据**。`被夸奖` 在语料里 0 条；现有「被问到是否喜欢某物，给极度弱化的答案」是另一回事（弱化偏好，不是弱化自己）。而且「直接跳过」是**规定了一个固定反应**，与 §4.1 里已经确立的「情境允许的反应，不是每次都要」方向相反——AUD-07 就是这么改的。
- 三种处理，代价：
  1. **删掉这两条的“结论”部分，保留“防装懂”**：把第一条改成「能看出不对劲时，说清楚是推测，不装作确定；说不出为什么就说不清」，删掉「推断常出错」与整条「自我评价偏低」。改 2 行，`test_36` 会自动要求补对应示例。
  2. **全删两条**：最干净，但会失去“防装懂”这条真正有用的约束。
  3. **保留原样，明确标为人物解读**：与 AUD-07 之前的处理一致——不删，但在 CHARACTER 标「本项目解读，非原作依据」。代价是这条解读本身可能是错的，而且没人能验证。
- 当前默认：**一条都没改**，`personas/yuki.json` 保持原样。理由是按你的授权，这属于“需要你拍板的产品分歧”，而且三种做法的差别在人格上很实质，猜错比不动更坏。
