## 零、一句话结论

两项修复都已完成，**失败先于修复被复现**（共 12 处断言先红后绿）。

但必须先把话说清楚：**P0 修复没有显著提升检索指标**。

| 口径 | 修复前 | 修复后 | 变化 |
|---|---|---|---|
| `main` Recall@5 | 73.0% | 73.0% | **无变化** |
| `main` Prec@5 | 25.0% | 25.0% | 无变化 |
| `main` MRR | 0.718 | 0.718 | 无变化 |

`all` / `low` 的提升**全部来自 D04 一条题**（下面 §四有逐题证据），不是普遍性改善。

**P0 的价值不在指标上，在三个别的地方**：

1. 「在吗」这类输入不再**静默穿透**——现在能报出「检索跑了但没找到」，而不是假装语料里没有；
2. 「不知道」不再被当成「知道」去检索；
3. 40 条被错标成崩溃世界的台词归位了。

这三件事在现有 60 条评测集里几乎测不出来，因为它们测的是**正确性**，而评测集测的是**召回率**。这个区别是本次报告最重要的一句话。

## 一、P0-1：分词退化与否定语义反转

提交：`14a11b7`

### 1.1 问题（修复前实测）

| 输入 | `tokenize()` | 后果 |
|---|---|---|
| `在吗` | `[]` | `search()` 直接 `return []`，检索**根本没启动** |
| `你在吗` | `[]` | 同上 |
| `是的` | `[]` | 同上 |
| `那个` | `[]` | 同上 |
| `是吗` | `[]` | 同上 |
| `不知道` | `['知道']` | **语义反转** |
| `不需要` | `['需要']` | **语义反转**，而「不需要」正是 `yuki.json` 唯一一条 verified 示例 |

### 1.2 中间过程：我走错了一版，记录在此

**第一版做法**：把 `_NEG`（否定字）从停用字里豁免，让 `tokenize` 保留「不」。

**结果**：`main` Recall 从 **73.0% 崩到 4.0%**。

**原因**（实测定位）：
- `tokenize` 决定 BM25 的**词表、df、IDF、文档长度**；
- 保留否定字后，「不确定」从 `确定` 变成 `不确` + `确定`，全库 2-gram 结构变了；
- IDF 全量重算，所有文档分数整体漂移；
- 首条查询 `你的工作是什么` 的正确答案从 **7.838 分掉到 6.011 分**，被噪声挤到第 3 名。

**第二版做法**（采用）：不碰 `tokenize`，另开 `tokenize_query`，只在**查询侧追加**否定双字。

**验证**：`你的工作是什么` 恢复 **7.838 分**，索引 `docs.jsonl` 的 md5 与修复前**完全相同**（`be0e48c6...`）。

> 这一步值得单独记：**「改分词」和「改索引」在 BM25 里是同一件事**。任何替换式的分词改动都会连带改排序，哪怕改动看起来只是"补回一个被误删的字"。

### 1.3 最终实现

```python
def tokenize(text)       # 建索引用。规则冻结，注释里写明为什么不能改。
def tokenize_query(text) # 查询侧。在 tokenize() 结果后追加：
                         #   否定双字（不知/不需/没说）
                         #   整段虚词的短句兜底（长度≥2 才退原串）
```

### 1.4 修复前后行为对照

| 输入 | 修复前 | 修复后 `tokenize_query()` | 检索状态 |
|---|---|---|---|
| `在吗` | `[]` → 静默跳过 | `['在吗']` | `no_match` ← 检索真的跑了 |
| `你在吗` | `[]` → 静默跳过 | `['你在吗']` | `no_match` |
| `是的` | `[]` → 静默跳过 | `['是的']` | `no_match` |
| `那个` | `[]` → 静默跳过 | `['那个']` | `no_match` |
| `是吗` | `[]` → 静默跳过 | `['是吗']` | `no_match` |
| `不知道` | `['知道']` 语义反转 | `['知道','不知']` | `no_match` |
| `不需要` | `['需要']` 语义反转 | `['需要','不需']` | `ok`（6 条） |
| `的` | `[]` | `[]` | `no_tokens` ← 单字虚词仍不检索 |

**注意 `在吗` 的结果是 `no_match` 而不是 `ok`**：语料里确实没人这样问，所以返回 0 条是对的。区别在于——**修复前它连找都没找，修复后它找过了、没找到**。调用方现在能分辨这两件事。

### 1.5 状态契约（用户第 2 项要求）

新增 `Corpus.search_detailed()` → `SearchResult`：

| 状态 | 含义 |
|---|---|
| `STATUS_OK` | 有命中 |
| `STATUS_NO_TOKENS` | 切不出 token，**检索没有启动** |
| `STATUS_NO_MATCH` | 检索跑了，语料里确实没有够格的记录 |

`Corpus.search()` 签名与返回类型**完全不变**（仍是 `list`），主线 T1–T6 无感。这一条被测试 `test_20_search_returns_plain_list` 钉住。

> 这里我一开始让 `search()` 返回 `SearchResult` 对象，`main` 立刻崩到 4.0%。原因是评测脚本对 `hits` 做了 `hits[i+1:]` 切片，而 `SearchResult` 没实现切片，静默失败。**改公开返回值类型是破坏性变更**，已回退。

## 二、P0-3：《消失》世界恢复点

提交：`99effb4`

### 2.1 问题

`build_corpus.py` 只切不还：从 `0:38:13` 一路把 `crash` 标到片尾字幕 `2:41:21`。

但 `2:33:26`「世界变回了原来的样子」之后，剧情已经回到主线：

```
2:33:13  私立光阳园学院又变回了女校     ← 女校 = 主线特征
2:33:26  世界变回了原来的样子           ← 明写的转折句
2:33:36  我和长门还有朝比奈必须再次回到过去
2:34:33  作为SOS团成员之一 我也要积极地保护这个世界
2:34:40  不久春日主办的圣诞节火锅派对就要开始了
2:36:13  等我尝过春日特制火锅之后再去也不迟吧
2:41:10  看 完成了                     ← 片尾字幕
```

crash 世界里的春日根本不存在，不可能有这场火锅派对。

### 2.2 边界认定：为什么是 40 条而不是审计时说的 46 条

审计阶段按「`2:33:01` 我健康地出院了」划出 **46 条**可疑。
实际修复以 **`2:33:26`** 为界，移出 crash 的是 **40 条**。

差的 6 条是 `2:33:01–2:33:25`：

```
2:33:01  我健康地出院了
2:33:03  今天是12月24日
2:33:06  结业式的早上
```

这几句是阿虚**叙述世界已恢复、但他自己还没意识到**的过渡段。它们仍处在叙述的"回过神来"瞬间，我选择把恢复点定在**明写的转折句**（`2:33:26`）而不是叙述内容上。

**这是一个判断，不是事实。** 如果认为「出院」就该算主线，把锚点改成 `我健康地出院了` 即可，测试会相应要求 46 条。当前选择更保守：宁可少移 6 条，也不让边界依赖推断。

```python
def detect_world_restore(rows, cut) -> float | None:
    # 只在 cut 之后找；找不到返回 None
    # None 时行为退回「全程 crash」= 修复前状态，不会比现在更差
```

同时把逐行世界归属抽成 `world_at(t)` 单函数——旧实现是「记录归属」和 `ctx_worlds` 各写一遍 `>= movie_cut`，加恢复点必然要同改两处，容易漏。

### 3.4 收尾时发现的一处漏网：`test_backend.py` 断言过时

上述 117 项里不含 `scripts/test_backend.py`（它需要真实语料，早前几轮跑的是不带 `-s` 的子集）。收尾做全量 `pytest scripts/` 时暴露了 1 处失败：

第 203 行硬编码了 `crash == 1574`。

**这是 P0-3 的正确后果，不是新 bug**：世界边界修正就是要让 crash 从 1574 变 1534。但断言不修，就变成"修完代码、测试还钉着旧事实"。

修法不是把 1574 改成 1534（那样下次改归属还会再挂一次），而是**改成钉不变量**：

```python
n_crash  = sum(d['world'] == 'crash'  for d in self.corpus.docs)
n_normal = sum(d['world'] == 'normal' for d in self.corpus.docs)
self.assertEqual(n_crash + n_normal, 13070)   # 总数与互斥性
self.assertTrue(0 < n_crash < 13070)          # 两世界都非空
```

世界边界的**具体取值**由 `test_world_boundary.py` 专项守护（恢复点检出、恢复后无 crash、切点区间仍是 crash、片尾归位）——那里钉得比一个数字严格得多。总数与互斥性则由这里钉，两者不重复也不冲突。

### 5.1 absent 类的核心缺陷**没有被 P0 修复**

`min_score=5.0` 过低、2-gram 高频片段匹配这两件事，本轮**没有动**（属于 P1）。所以「你怎么看量子纠缠」仍然以 14.30 分召回无关内容。

**这是有意为之**：调 `min_score` 会砍掉正确答案（`你的工作是什么` 的相关结果最低只有 5.93 分），必须等 §六 的「本句为主」改造完成、分数区分度恢复后才能重估。

## 七、本轮新增的风险

| # | 风险 | 严重度 | 说明 |
|---|---|---|---|
| R-1 | 短句兜底可能让「在吗」类输入命中无关原句 | 低 | 原串 token 的 IDF 很高，实测 `在吗` 仍返回 `no_match`。但若语料里恰好有「在吗」，会命中——这是符合预期的 |
