## 零、先说一条必须更正的结论

> **「12 次自然聊天全部是纯文字，未观察到自主出图」——这句话与它自己的数据不符。**

用 `art_blocks()` 重数上一轮的 24 条采样（`--recount-only`，可复跑）：

| 组 | 轮数 | 含图案块 |
|---|---|---|
| B 组自然聊天 | 12 | **1** |
| A/C 组明确要求 | 36 | 13 |

那一次是 **B2 rep1 turn2**，输入只有「杯口的热气慢慢往上飘。」，她回的是：

```
（盯着那几行看了会）

    (  )
     (  )
   ┌────┐
   │    │
   └────┘

看着就觉得暖和。这种天气，手里有个热的东西挺好的。
```

**这是自主出图。** 上一轮把它数成 0，原因是汇总用的是 `is_art()`：

- `is_art()` 回答的是「**整条**是不是画」；
- 而真实输出几乎总是「一句话 + 一张图 + 一句话」，文字行占多数，
  整条必然 `is_art=False`；
- 于是**只要她画的时候还在说话，就永远数不到**。

正确的量是 `art_blocks()` / `has_art_block()`（上一轮修 R-ART-04 时刚加的那个）。
拿 `is_art` 数自主出图，是一个会稳定输出 0 的口径错误——不是模型没画。

**这条更正不改变「自主出图仍未验证」的结论**，但改变了它的形状：
问题不是「她从不主动画」，而是「**她偶尔会画，但频率低、时机难以预测**」。
两者要查的东西不一样。

## 一、她会不会自然想画点什么（C 类）

### 1.1 怎么问才算「绘画机会」

新写 `scripts/sample_art_spontaneity.py`。场景纪律：

- 用户句子里**不出现「画」「图案」「字符」**，也不评价她的表达能力；
- 只给「适合视觉表达」的处境：描述一个说不清的东西、问她那边什么样、
  情绪到了、回忆一个形状、想说又说不出来；
- 每场景 4 轮连续对话；多轮才看得出关系累积之后会不会动笔。

### 1.2 基线：20 轮，0 次

5 个场景 × 4 轮 = 20 次真实生成，24/24 全部正常结束（HTTP 200、`finish_reason=stop`、
`[DONE]`），**含图案块 0 轮**。

但要看清它为什么是 0——有两轮她**已经走到画的门口又停住了**：

| 场景 | 输入 | 她的回答 |
|---|---|---|
| D1 turn3 | 你要是能看到就好了。 | ……嗯。看不到的话，就只能听你说。不过你说的时候，**我大概能拼出一点来**。 |
| D1 turn2 | 就是那种，看一眼就知道是它，但要描述就不知道从哪说起。 | （想了想）嗯……那就先不管它长什么样。它是什么颜色的，凉的还是温的，会不会动。 |

第二轮她说「我大概能拼出一点来」，**下一轮没有拼**。这不是能力问题，
是她选择了继续用问题接话。这比「0/20」这个数字本身更有信息量：
**缺的不是意愿，是一个让她觉得值得动笔的时机。**

### 1.3 对照消融：是措辞压住了吗

同一批场景（D1 + D3，各 4 轮），只替换内存里的 `pb.ART_PROMPT`，**不落盘**：

| 组 | 改了什么 | 含图案块 |
|---|---|---|
| E1 | 删掉三句劝阻（「不画才是大多数时候的样子」等） | 0/8 |
| E2 | 删劝阻 **+ 写明邀请**（「对方描述一样东西、说不清楚的时候，画出来比解释更省事」） | **1/8** |
| E3 | 原样重跑（对照组，检验随机性） | 0/8 |

E2 那一次画的是雨：

```
  /  /  /
 /  /  /
/  /  /
站很久的话，腿会有点酸吧。我这边看不到外面，不知道有没有在下雨。
```

**怎么看这个结果**（三条都要说清，不能只挑一条）：

1. **劝阻句不是主因**。删掉三句劝阻（E1）出图率仍然是 0/8。
   所以「不画才是大多数时候的样子」这类话**不是**压住她的东西。
2. **明确邀请能动它**。E2 加了「画出来比解释更省事」之后出现 1/8。
   但这是 **1 个样本**，而且 E2 那句邀请**等于给了配额式触发**，与 DEC-007
   直接相反。所以这个结果只能证明「措辞能左右出图」，**不能**当成「应该这么改」。
3. **随机性确实很大**。E3 原样重跑的 8 轮与 D 组基线同条件，都是 0。
   同一条件下 0/8 与 1/8 的差别，不足以谈频率。

> **消融是诊断手段，不是提案。** 三条都只在内存里换常量，`prompt_builder.py`
> 与 `personas/*.json` 一个字都没改（`ART_PROMPT` 前后 SHA-256 一致，
> `params.json` 里记着基线 sha 与各消融的 sha）。

### 1.4 一次空回复（如实记录）

E3 的 D3 turn2 返回 **HTTP 200、`finish_reason=stop`、收到 `[DONE]`，正文为空串**。
全库 92 条采样里只有这 1 条是这样（另有 12 条 503 是桥断了，属于另一类）。

这不是假想的边界：**模型返回了合法的空内容**。前端此时显示「……」并把这一轮存进历史
（`web/index.html` 那条 `stripPrefix(acc) || "……"`），不会崩，也不会假装收到过内容。
但**「她只回一个省略号」与「上游什么也没给」在记录里长得一样**，
以后查「她为什么突然不说话」时会分不清。已记在这里，未改行为——
`……` 是协议允许的合法空应答（TERMINAL_PROMPT 第 3 条），改成报错反而是错的。

## 二、字体对照（PEND-010 的取证）

### 2.1 上一轮的结论里有一条查不到出处

上一轮（以及 2026-10-23）的记录写着：

> 「逐字体测过本机全部等宽字体：只有 `Noto Sans Mono CJK SC` 的汉字:ASCII 是 2」

**本机没有这个字体。** 注册表里只有 `Noto Sans SC` / `Noto Serif SC`，
`scripts/font_probe.js` 逐个探测也判它「未安装」。那条结论无法复现，
本轮不再引用。

### 2.2 0.53px 不是字体设计差异，是**回退字体**

上一轮量到 `a` = 7.97px、`⣿` = 8.50px，据此说「盲文格可能错位」。
本轮把字体栈逐级缩短，看这个值在哪一级变化：

| 字体栈 | a | 框线 | 方块 | 盲文 |
|---|---|---|---|---|
| `"Consolas", monospace` | 7.97 | 7.97 | 7.97 | **10.92** |
| `"Consolas","Cascadia Mono", monospace` | 7.97 | 7.97 | 7.97 | **8.50** |
| `"Cascadia Mono", monospace` | 8.50 | 8.50 | 8.50 | **8.50** |

结论很清楚：**Consolas 里没有盲文字形**（`native.braille = False`），
浏览器逐字回退到栈里下一个有盲文的字体（Cascadia Mono，8.50px）。
所以 7.97 与 8.50 是**两个不同字体**的宽度，不是同一个字体里两种字符的差异。

**回退是不是问题，取决于它是否与 ASCII 同格。** 实测：

- 只要盲文来自 `Cascadia Mono`，它就和该栈里的 ASCII **完全同宽**（0.5239 = 8.4961 − 7.9722），
  即**每格差 0.52px 是「和 Consolas 的 ASCII 比」，不是「盲文自己会漂移」**；
- 把 Cascadia 提到 Consolas 之前（候选 A），四类符号**全部同宽**：
  `a` = `│` = `█` = `⣿` = 8.496px，符号离散度 **0**，20 格漂移 **0**。

### 2.3 全字体扫描：有字体能同时满足两项，但没有一个能同时满足四项

`scripts/font_probe.js --from-registry` 逐个量了本机 **205 个已装字体**
（数据 `out/font-probe-20261026/all-fonts.json`）。判据分成两项：

- **一格齐**：ASCII、框线（`│─┌`）、方块（`█░`）、盲文（`⣿`）四类都等于 `a` 的宽度；
- **汉字两格**：`雨` 正好是 `2 × a`。

| 字体 | a | 框线−a | 方块−a | 盲文−a | 汉字/a | 一格齐 | 汉字两格 |
|---|---|---|---|---|---|---|---|
| **Cascadia Mono** | 8.50 | 0 | 0 | **0** | 1.77 | **是** | 否 |
| **Cascadia Code** | 8.50 | 0 | 0 | **0** | 1.77 | **是** | 否 |
| 当前页面栈（Consolas 优先） | 7.97 | 0 | 0 | **+0.52** | 1.88 | 否 | 否 |
| Consolas | 7.97 | 0 | 0 | +2.95 | 1.88 | 否 | 否 |
| SimHei / 幼圆 / 隶书 / KaiTi / FangSong | 7.25 | +7.25 | +7.25 | +3.67 | **2.00** | 否 | **是** |
| SimSun / NSimSun | 8.00 | +7.00 | +7.00 | +2.92 | 1.88 | 否 | 否 |

**同时满足「一格齐」与「汉字两格」的字体：一个也没有。**
这与 2026-10-23 的结论一致，但那一轮举的 `Noto Sans Mono CJK SC` 例子是错的，
本轮换成 205 个字体逐个量出来的表。

### 2.4 一条要一并交代的事实：`█` 与 `░` 的字墨

第一版判据把「字墨比格宽大」当错误，结果是 `─`（横线本来就该跨格连接）被报成「有缝」。
**方块与盲文是当像素用的，相邻两块必须边缘相接**——留缝才是问题，墨略出格是正常的。
判据已改为只看**正缝**。这一条写在对照页的说明里，免得下一个人再改回去。

### 2.5 交付：可以自己在浏览器里比

- **`web/font-preview.html`** — 自带说明的对照页，同时报**排版宽度**与**字墨宽度**
  两个量（这一区分是本轮补的：只量 advance 会得出「每个字一样宽所以没问题」，
  只量 ink 会漏掉累计漂移）。分四节：当前字体、本机候选、四类样本的实际渲染
  （正常字距 / 字距 0.04em 对照）、原始 JSON。
- **`scripts/font_preview_check.js`** — 用真实 headless Edge 打开它、取数、截图留档
  （`out/font-preview-20261026b/`，含整页与 390px 窄屏）。
- **`scripts/font_probe.js`** — 按字体名逐个量、并**判断该字是否来自本字体**
  （靠「加兜底后宽度是否变化」）。这是 2.2 那条结论的取证工具。

**本轮没有安装任何字体、没有引入 web font、没有改 `web/index.html` 的字体栈。**
`PEND-010` 仍然是待你决定的事项，本轮只补证据。

## 三、这一轮修掉的两条真缺陷

### R-ART-05 · 顶格的脸让整只猫拼不成一块（本轮最严重）

- **复现输入**：上一轮真实采样 A1 rep2 的原样输出
  ```
   /\_/\
  ( o.o )
   > ^ <
  ```
- **改前实际结果**：`art_blocks()` 返回**一块普通文字**，不是图案块。
  界面按文字排版，行首空格被折叠，脸和嘴对不上耳朵。
- **原因**：`_signals()` 要求「连续 3 个图案字符」，`( o.o )` 被两个字母隔成散符号，
  最长连续串只有 1。**同一只猫只要脸那行缩进 2 格（A1 rep1）就能成块**——
  这说明漏判的是判据，不是模型画得不对。
- **影响面**：真实输出里「顶格的脸」不罕见；这正是「她画了但界面没当画」那一类。
- **修法**：新增 `_art_line_kind()`，分 `hard`（原判据）与 `soft`（新）两级。
  `soft` 很窄：行宽 ≤ 16 格、符号占非空格字符 ≥ 1/3、至少 2 个图案字符、
  **且不以框线字符开头**（保住 PEND-011 的表格取舍）。
  再加一条硬约束：整块里**必须有 hard 行**，`soft` 只能补齐、不能自己起块。
- **验证**：`test_textart.py::test_49/50/51`；真实浏览器 `@cat_flat` 样本
  （块结构 `blk art`、行首空格 `[1,0,1]` 保留、无 `△`、375px 无横向溢出）。

### R-ART-06 · 收缩之后不能反向误伤：表格行与普通文字

`soft` 的门槛单看很低，所以 `test_50` / `test_51` 同时锁住相反方向：

- 两行「过 soft 门槛但没有 hard 行」的普通话（`x=1;y=2` / `k=3;j=4`）**必须不成块**；
- `│ ok │` 这种框内写字的表格行**必须仍不升级**为图案行。

**这两条第一版没锁住。** 变异 M77 一开始「未拦住」，查下去发现是我挑的样例
（`好 / 不好`）**根本没过 soft 门槛**——用例在测「它本来就不是 soft」，
把约束删掉也照样绿。换成 `x=1;y=2` 才真正拦住。

> 这正是 VALIDATION §一 那条规矩的价值：**先确认用例会红，再相信它绿。**

## 六、过程中踩到的坑（都留在测试里）

### 6.1 变异锚点在我改代码之后静默失效

全量第一遍跑出「74/78」，其中 M37/M38/M68/M69 四条不是「没被拦住」，
而是**根本没改成**——我重构 `art_blocks()` 时改了主循环的写法，
四条变异的字符串锚点对不上，`assert` 自己失败了。

`mutation_check.py` 把它们标成「变异失效」并**以非 0 退出**，
没有混进「已拦住」。这是 2026-10-25 复核时加的判定，这次真的救了场。
锚点已按新代码修好，单跑 4/4 报红。

**这条要写进流程**：改被变异的代码，必须同步检查变异锚点。

### 6.2 一条 `未确证` 的变异，查下去是**解释器级崩溃**，根因是索引加载竞态

全量第二遍跑出「77/78」，剩下一条 **`未确证`**：不是「没被拦住」，而是
「进程异常退出、拿不到断言证据」。**单跑那条 3/3 都能拦住**，只有全量才出事。

没有把它当偶发略过，继续查：

1. 日志里是 `ValueError: generator already executing`，
   位置在 `retriever.py::tokenize` 的生成器表达式；
2. 写探针用 8 线程 × 400 次**并发调用** `tokenize()` —— **复现不出来**；
3. 换个方向：用 6 线程反复**重建索引**，6 次里**崩了 2 次**，
   退出码 `-1073741819`（`0xC0000005` 访问冲突）。
   再跑全量，这次崩的是**另一条变异**（上一遍 M46、这一遍 M3），
   而 M3 的日志里出现的是 `Fatal Python error: _PyEval_EvalFrameDefault:
   Executing a cache`。

也就是说：**每次全量都会崩一次，崩在哪条变异上是随机的。**
继续缩小范围，找到了根因——`server.py` 的惰性加载：

```python
def load_corpus():
    global CORPUS
    if CORPUS is None:          # ← 先查
        CORPUS = Corpus(INDEX)  # ← 后建，中间没有锁
    return CORPUS
```

`ThreadingTCPServer` 每个请求一个线程。窗口里进来的线程都会看到
`CORPUS is None`，于是**同时构造多份 13070 条的索引**。实测 6 个线程同时进来：

| | 构造次数 | 拿到的对象 |
|---|---|---|
| 改前 | **6** | 6 个互不相同 |
