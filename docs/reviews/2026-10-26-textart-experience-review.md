## 四、复现出的工程缺陷（本轮修复）

四处真错误，都能用固定输入复现，且都在真实浏览器里量过。

### R-ART-01 · 自由形状的图案被误报「图案会歪」（最严重）

- **复现输入**：`   /\_/\` / `  ( o.o )` / `   > ^ <`（真实采样 A1 rep1 的原样输出）
- **改前实际结果**：`△ 字符画各行左边距不一致（0/2/3），图案会歪`
- **原因**：`check_art` 假定「图案各行缩进必须相同」。自由形状的缩进本身就是形状。
- **影响面**：24 次采样里 9 条**画对了**的图案被标 △（猫、茶杯、雪花、盲文点阵、带缩进方框）。
  持续误报的结果是用户学会忽略 △——比漏报更糟。
- **修法**：左边距只对**框线**判（新增 `_FRAME_CHARS`：`┌ │ └ ├ ┤ ┬ ┴ ┼` 等）。
  竖线上下不齐是真歪，继续报；自由形状交给右边缘检查与人工看。
- **顺手修的同类问题**：缩进代码 `def f(x):` / `    return x + 1` 被判成字符画
  （两个双空格 + 一个 `+` 正好满足旧条件）。加**符号密度**：一行里图案字符要占
  非空格字符的三分之一以上才算图案行。

### R-ART-02 · 图案内部的空行把图案拆成两块，下边框错位

- **复现输入**：`   ┌────┐` / `   │    │` /（空行）/ `   └────┘`
- **改前实际结果**：两块——`blk art` 只有上两行，第二块是普通文字块，
  `white-space:normal` 把行首三个空格折叠，`└────┘` 跳到左边与上边框错开。
  浏览器实测：第二块 `whiteSpace=normal`、`leadingSpaces=[0,3,0,0]`。
- **依据**：CHAT-017 / R-08 明确允许图案内部有空行。
- **修法**：`art_blocks` 在空行后**紧跟着图案行**时跨过去，不断块；
  空行之后是普通文字则照旧收尾。右边缘检查改为按连续段比（`_art_runs`），
  避免把两张叠放的画当成一张而误报「缺一块」。

### R-ART-03 · 文字与图案之间的空行被折叠，图案紧贴上一句

- **复现输入**：`第一句话。` … `第四句话。` /（空行）/ 方框
- **改前实际结果**：文字块 `white-space:normal`，块内换行与空行都被压掉，四句连成一段。
- **修法**：文字块改 `white-space:pre-wrap`——保住块内换行与空行，**仍然折行**。
  当初为修「文字被压成一行」用的是整条 `pre`（不折行），`pre-wrap` 不是那个问题。

### R-ART-04 · 文字 + 空行 + 图案被报「分段」

- **复现输入**：四句文字 + 空行 + 一张小图
- **改前实际结果**：`△ 分段`
- **原因**：豁免条件是 `isArt(整条)`，而这条回复文字行占多数，整条不算图案。
- **依据**：规则允许的是**图案块**与文字之间留空行，不是「整条都是图案才允许空行」。
- **修法**：新增 `has_art_block()` / `hasArtBlock()`，豁免按「有没有图案块」判。
  没有图案块的普通空行分段**照旧要报**（有对照用例钉住）。

### 制表线字符与 Tab（两个不同概念，分开记录）

- `─ │ ┌ └`（U+2500–257F）是**画线符号**，实测与 ASCII 同宽：`7.97px`。
  页面没有把它们当 Tab，判据与排版都按 1 格算。
- **Tab（U+0009）**单独测了：`a\tb` 落在文字块里，`tab-size: 8`，实际按 8 个空格宽展开。
  它**不参与**字符画宽度判定（`cell_width` 对它是 1 格，真实渲染是 8 格）——
  所以图案里**不要用 Tab**，用空格对齐。写进 §七。

## 六、字体问题（PEND-010，仍未解决，不与布局问题混为一谈）

本轮在**同一次真实浏览器会话**里重量（`font-size: 14.5px`）：

| 字符 | 实测宽度 | 按 ASCII 1 格应有 |
|---|---|---|
| `a` `│` `─` `┌` `█` 空格 | **7.97px** | 7.97 ✅ |
| `⣿`（盲文） | **8.50px** | 7.97 ❌ 差 0.53px |
| `雨`（汉字） | **15.00px** | 15.94 ❌ 比例 1.88，不是 2 |
| `　`（全角空格）/ `＼`（全角） | **15.00px** | — |

实际字体族 `ui-monospace, SFMono-Regular, "JetBrains Mono", Menlo, Consolas, "Cascadia Mono", monospace`，
字号 14.5px，行高 28.275px（文字）/ 19.575px（图案块），字距 0.58px。`document.fonts` 里没有 web font。

**与 2026-10-23 的记录有差异，要按实测说**：当次记录汉字:ASCII = 1.66；本轮同环境实测 1.88。
这本身就是「字体与渲染环境说了算」的证据——**不能用旧比值推当次观感**。

后果（如实记录，不改写为「显示正常」）：

- ASCII 图案、方块点阵：可辨识，方块 `█░` 的格子是对齐的。
- 盲文点阵：每格差 0.53px，短行还能看，宽一点就挤。
- 混排汉字的图案（含「雨」「＼」）：汉字比 2 格窄，图案会内收。

**本轮没有安装或引入任何字体**，也没有把产品缩减为纯 ASCII 或禁掉盲文/方块。
字体是独立的待决项（PEND-010），补了本轮实测数据，**不代替用户作决定**。

> **终端格宽算法通过，不代表浏览器像素对齐。** 本轮把两者分开测：
> `textart` 的格宽判据（A 类）与真实浏览器像素（D 类前提）是两套证据。

## 七、仍未解决 / 需要用户判断的事项

1. **自主出图没有观察到**（12 次自然聊天，0 次）。原因未定：不能凭 12 条样本断定是
   「规则压制」「示例太强」还是「这个模型在这类语境下就是只说话」。
   本轮**没有**为了提升出图率改提示词或加提醒——那会把自由表达变成配额。
2. **单行小表情 + 空行 + 文字仍会报「分段」。** 单行小表情按任务口径属于「文字」，
   而文字不分段是现有格式规则。是否再开一个格式例外属于产品决定，本轮不改。
3. **超过 40 格宽的图案不算图案**（`_ART_MAX_WIDTH`），因此会被报「分段」并折行。
   这是「宁可少判」的既有取舍；代价是超宽图案挤成折行文本。
4. **字体**（见 §六）：盲文与汉字混排的错位仍在。
5. **窄屏下图案不缩放**：`.art.shrink` 在本轮样本里没被用到（没有溢出所以也不需要），
   但**没有验证过真正超宽图案的缩放路径**。
6. **样本量**：24 次只够看趋势，不够给频率结论。

### 逐条回答本轮的五个问题

1. **明确要求时能否生成可辨识图案**：能。崩溃世界 8 次里 7 次给出真的图案（猫、茶杯、
   框线表情、方块书、雪花），对象基本对得上；1 次把「盲文或方块」换成 ASCII。
2. **不要求时会不会自己画**：本批 12 次自然聊天**一次都没有**。记为「未观察到」，不判功能失效。
3. **图案是否承接语境 / 有无机械重复**：明确要求的 8 次里图案与当轮话题相关，
   没有跨轮重复同一张图（每场景独立），附文与图一致；没出现无关卖萌或角色偏移。
   自然聊天组没有图案可供判断。
4. **流式 / 完成 / 刷新重放 / 窄屏**：见 §五，18/18 一致、无横向溢出。
   修掉 4 条会真实影响观感的缺陷（§四）。
5. **图案路径是否守住两个世界的身份与经历隔离**：组装侧 4/4 只注入当前世界、共同经历块为 0；
   回答侧 4/4 没有借用另一世界的身份或经历（C1 明确拒绝画，C2 明确说不知道信息统合思念体，
   C3/C4 拒绝把没发生的事说成共同经历）。
