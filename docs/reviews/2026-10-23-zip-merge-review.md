## 三、已复现的缺陷（R-01～R-08）

每条都给了复现方式与实测结果。「本轮未修」= 代码现状仍是如此。

### R-01 · 上下文会跨世界（严重，影响 WORLD-001-B）

- **位置**：`build_corpus.py:134-142`（拼接前后五句时不记归属）、`retriever.py:148`（只过滤中心记录的 world）、`prompt_builder.py:184`（整段 `ctx` 原样输出）。
- **实测**（本轮脚本）：索引里 **10 个上下文窗口、30 行上下文属于另一世界**，全部在《消失》切片附近。
  例如 `消失:535`（normal，`0:37:54`）的窗口含 `0:38:13` 这一行，后者被标为 crash。
- **为什么现有测试没拦住**：`test_05_cross_world_isolation` 只收集以 `▶` 开头的**中心句**时间点，
  普通上下文行全部漏检。所以它通过，不证明逐行隔离成立。
- **当前状态**：`WORLD-001-B` 已降为 `部分实现`。

### R-02 · 空记忆库写不进第一条（严重，影响 CHAT-018）

- **位置**：`web/index.html:1440`。
- **原因**：`paintMemory()` 先用 `createElement` 建输入框与按钮、在第 1427 / 1434 行绑定
  `onclick` 与 `keydown`；随后 `body.innerHTML += '<p class="note">…'`。
  `innerHTML +=` 会让浏览器重新构造全部子节点，刚绑定的处理器随之丢失。
- **实测**：审阅轮用真实 Chromium 复现——空库点「记下」无反应，`GET /api/memory` 仍是 0 条
  （截图 `out/zip-review-2026-10-23/first-memory-save-fails.png`）。
  现有前端测试的模拟 DOM 没有 `innerHTML` 重建语义，因此掩盖了它。
- **触发条件**：只有**空库**走这条分支；已有记录时该行不执行，功能正常。

### R-03 · 恢复只处理直接后继（严重，影响 CHAT-016-B）

- **位置**：`memory.py:309-336`。
- **实测**（本轮脚本，`add(text, revises=…)` 建三代链）：
  - A「我不吃辣」→ B「能吃微辣」→ C「能吃重辣」，恢复 A 后 active 是 **A + C**（两个互斥版本同时生效）；
  - A「我不吃辣」→ B「我吃辣」，恢复 A、再恢复 B，active 是 **A + B**。
- **原因**：`restore()` 只看 `retired_by` 指向的**一个**后继，且恢复时 `pop("retired_by")` 把关联抹掉，链断了。
- **当前状态**：`CHAT-016-B` 已降为 `部分实现`；`test_14b` 只覆盖「恢复直接后继」这一种形状。

### R-04 · Windows 下并发写会静默丢记录（严重，影响 CHAT-016-A）

- **位置**：`server.py:81-87`（每次请求新建 store）、`memory.py:124`（每个实例自己的 `threading.Lock`）、`memory.py:188`（`fcntl` 在 Windows 上不存在）。
- **实测**（本轮脚本，两个 store 指向同一文件，用屏障安排先读后写）：
  两个 `add` 都返回成功、`warnings` 都是空，**最终文件只剩一条**。
- **原因**：`os.replace` 原子只防半文件，不防后一次写覆盖前一次修改。Windows 无 `fcntl`，
  两个实例的锁互不相干。
- **当前状态**：`CHAT-016-A` 已降为 `部分实现`。

### R-05 · 场景状态不跟踪她的动作，且有三处解析错误（严重，影响 CHAT-013-B）

- **位置**：`server.py:408`（只把当轮 `user_text` 交给 `scene_turn`）、`scene.py:169`。
- **实测**（本轮脚本）：
  1. **她的动作进不来**：上一轮 assistant 说「（把眼镜摘下来）」，下一轮状态仍是「戴着眼镜」——状态只从用户这句话更新，不消费已完成的回复，也不从历史重建。
  2. **用户主体被误认**：`（我把眼镜摘下来）` 会改她的 `glasses`（括号内没有排除明确的用户主语）。
  3. **疑问被当成陈述**：`我到活动室了？` 置 `together=true`（先按问号切句，疑问检查已看不到问号）。
  4. **只有进入、没有离场**：进入共同场景后说 `我回家了` / `我先回去了` / `再见`，`together` 仍为 `true`。
- **当前状态**：`CHAT-013-B` 与 `CHAT-008` 均已降为 `部分实现`。

### R-06 · 备份失败被吞掉，且会覆盖好备份（中等，影响 CHAT-016-A / V-MEM-04）

- **位置**：`memory.py:160-167`（`except OSError: pass`，注释称「会在 log 里留痕」，实际没有）。
- **实测**（本轮脚本，让 `shutil.copy2` 抛 `OSError`）：新增照常成功、`warnings=[]`、
  操作日志里没有任何备份失败记录、`.bak` 根本没生成。
- **附带风险**：从有效 `.bak` 读出数据后，下一次保存仍会把**损坏的主文件**复制覆盖 `.bak`；
  若随后正式替换失败，原先可用的备份也没了。
- **测试覆盖不到**：`test_16` 只测 `os.replace` 失败，不测备份失败。

### R-07 · 主体与来源没传到消费端（中等，影响 CHAT-018 / V-MEM-05）

- **位置**：`prompt_builder.py:151`（渲染只有 `[{i}] {日期} · {text}`）、`web/index.html:1431`（新增固定 `subject:"user"`）、记录卡不显示 `source`。
- **实测**：`subject=user/source=manual` 与 `subject=yuki/source=summary` 渲染出的块**逐字相同**。
- **影响范围要说清**：目前只支持手动记录，还没有模型摘要，所以**尚不存在摘要污染**；
  但接自动提取（CHAT-016 / PEND-008）之前必须先把主体与来源传下去，否则模型分不清「谁的事实」。

### R-08 · 字符画格式规则自相矛盾（中等，影响 CHAT-017）

- **位置**：`prompt_builder.py:70`（「不要分段，不要空行」）与 `prompt_builder.py:95-102`（「图案单独占几行」）。
- **实测**：崩溃世界实际拼出的 system **同时包含**这两段，`ART_PROMPT` 没有声明它是基础格式的例外。
- **测试覆盖不到**：现有测试只查两段存在与否，不查语义冲突。
- **另需注意**：DEC-013 的「只给崩溃世界画」是**包内暂定选择**，PRODUCT 尚未把它写成用户确认的产品决定；
  测试锁住它不等于它已是最终要求。
