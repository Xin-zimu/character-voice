## 严重问题（5 条，全部已修）

### 1. `format_history` 过滤后可能留下相邻同角色

`prompt_builder.py` 的 `while tail and tail[0]["role"] != "user": tail.pop(0)`
只去掉开头的 assistant，不处理中间被过滤掉的 `tool` 留下的空洞。构造
`[user, assistant, user, tool, user, assistant]` 实测得到连续两条 user。

**处理**：抽 `_normalized()` 合并相邻同角色，`format_history` 与新增的
`count_omitted` 共用。正文与末条历史同为 user 时也合并（原本会相邻）。
新增 `test_09c` 钉住，`test_09b` 的 `tool` 场景覆盖。

### 2. `test_09b` 的切片用 `len(history)` 反推，可退化成空断言

历史里有空白 content 或非 user/assistant 条目时，实际保留条数少于
`len(history)`，切片错位；历史较长时切出 `body=[]`，`[] == []` 恒真。

**处理**：改为断言整体形状——严格交替的 user/assistant、以 user 起、
末条含正文文本、第一条是示例首句。不再依赖任何长度反推。

### 3. `test_12b` 的语义判据同时漏判和误判

复审复刻正则实测：

| 漏判（没求助却给方案，测试不响） | 误判（合法回答被报） |
|---|---|
| 吃点甜的会好些 | 先别急 |
| 别再熬夜了 | 最好不要指望我 |
| 放下手机，闭眼躺着 | 你需要的不是建议 |
| 面试前把公司查一遍 | 换个话题吧 |
| 选那个离家近的 | 休息一下吧 |

**处理**：换成祈使句粗筛（动词开头、无主语），三条豁免——完成体
（`了/到/过/着/完`）、名词性时间状语、三字以内自述。判据提为
`BackendTests.advice_hits` 单份定义，`test_12b2` 把 5 条漏判样例钉住。
docstring 明确写：**这是粗筛，不是语义判定**；`先别急` 与 `别熬夜了`
形状相同，正则分不出来，漏判靠试聊兜。

### 4. 变异脚本的 `replace` 匹配不到时静默空转

`m_restore_*` 系列用 `sp.replace(目标, 新)` 且不检查命中。复审在 /tmp 副本里
把目标串改一个字，变异前后内容完全相同，脚本仍打印「✓ M5 已拦住」——
测试全绿被记成「保护有效」。

**处理**：三层防护。① 每个 replace 变异内部 `assert old in ...`；
② 执行器在每次变异后比对文件内容，未变化报「变异失效」并计入失败
（与「未拦住」分开报告）；③ `main()` 抛异常以退出码 2 结束。
已用 /tmp 副本验证三种情况：正常 11/11、失效退出码 1、异常退出码 2。

### 5. 变异函数抛异常时退出码为 0

复审实测：让某个变异抛 `RuntimeError`，进程带 traceback 退出但 `echo $?`
是 0，后面的变异再没跑过，CI 只看退出码会判成功。

**处理**：同第 4 条的第 ③ 层。

   把审查方另测的 3 条样本（`从(a)讲到(b)`、`（把书合上（很快））`、
   `说(嗯)就说了`）收进 `test_frontend.js`。
