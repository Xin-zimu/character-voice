## DEC-001 · 取消回复字数硬限制

- 状态：已确认（代码未实现，见 [STATUS.md](STATUS.md) CHAT-003）
- 日期：2026-10-21

**原方案**
主线人格卡规定「日常 ≤ 15 字、任务 ≤ 80 字」，学校卡「≤ 60 / ≤ 120」。前端与 `check_persona.py` 各自实现一套超字数判定，超出即在界面上标 `△`。

**现方案**
取消数字上限。规则只保留「通常话少、表达克制，必要时可以完整表达」。字数统计移出主聊天区，进调试面板。

**为什么改**
字数上限把「像不像她」简化成了「够不够短」，结果模型为了凑短而漏信息，长一点的回复反而被判为跑偏。真正的角色特征是**表达的克制**，不是字符数。

**影响面**
- `personas/yuki.json`、`personas/yuki_school.json`：删 `guard.max_chars_*`，改 `system_prompt` 第 1 条
- `prompt_builder.py::TERMINAL_PROMPT`：删字数档位
- `web/index.html::checkReply()` 与 `scripts/check_persona.py::simulate_check_reply()`：删长度判定（**必须同步**，见 DEC-006）
- `scripts/test_backend.py::test_08_persona_fields_preserved`：断言字段存在，需同步调整
- `README.md`、`scripts/check_persona.py` 的平均字数警告：从「判据」降为「参考」

## DEC-002 · 跨世界从「降权注入」改为「严格隔离」

- 状态：已确认（代码未实现，见 [STATUS.md](STATUS.md) WORLD-001）
- 日期：2026-10-21

**原方案**
检索时另一条世界线的片段降权 12% 但**不过滤**。`prompt_builder.py` 给它打上 `〔另一条世界线〕` / `〔未被修改的时间线〕` 标签，并追加 `CROSS_WORLD_PROMPT`，明确告诉她「偶尔会有一个片段浮上来，你可以说『有一件事，我不确定是不是真的』」。README 称之为「玩法本身，不是 bug」。

**现方案**
未经授权，另一世界的信息不得进入回答。取消降权机制与跨世界提示，检索时按当前世界过滤。将来同步记忆必须由用户选择内容与目标世界并明确确认；**切换世界本身不构成授权**。

**为什么改**
「漏话」会让两个世界各自的身份和经历失效——崩溃世界的她一旦能说出主线的事，她就不再是那个不知道信息统合思念体的普通高中生。而暗示性的「有件事我不确定」比直接说错更糟：它让边界变得不可验证，用户无法判断她到底知不知道。

**影响面**
- `retriever.py::Corpus.search()`：`other` 分支的 0.88 权重改为过滤
- `prompt_builder.py`：删 `render_hits()` 的跨世界标签、`CROSS_WORLD_PROMPT`、`build_messages()` 的 `other_world_touched`
- `server.py::_compose()`：删 `other_touched` 计算
- `scripts/test_backend.py::test_05_cross_world_preview`：**反向重写**（现断言「必须出现」，改为断言「不出现」）
- `README.md`「记忆怎么共享」整段作废
- 注意：crash 世界里出现「春日」「朝比奈」字样**不等于**污染，那些是剧情内讨论消失的春日（实测 crash 侧 `凉宫春日` 10 处、`朝比奈` 42 处）。判断污染看片段归属，不看关键词。

## DEC-003 · 语料准入分「剧情参考」与「角色台词」两轨

- 状态：已确认（文档已更新，代码无需改动）
- 日期：2026-10-21

**原方案**
`data/README.md` 写「**只有 L2 可以进入 prompt**。L0 / L1 是检索与标注的输入，不是语料。」

**现方案**
承认两种不同用途，各有各的门槛：
- **剧情参考**（这段对话里发生了什么）→ L0 原文 + 上下文即可，**不要求**说话人标注
- **角色台词依据**（这句是她说的话）→ 必须是 L2 人工核定

**为什么改**
原表述与实现直接矛盾：`prompt_builder.py::render_hits()` 一直在把未标注的 L0 字幕作为「原作记录」注入 system prompt。矛盾不在于实现错了，而在于文档用了**单一门槛**去管两种用途。检索层遵守的原则本来就是对的——「台词没有说话人标注，就不声称是谁说的」——只是文档没把这层区分写出来。

**影响面**
- `data/README.md`：重写为准入双轨
- 代码不改：`render_hits()` 的行为符合「剧情参考」定位
- 风险提示：**不得**因为「反正 L0 能用」就把它当 few-shot。示例仍须手写并带 `source`

## DEC-004 · 文档规范：产品决定与实现状态分离

- 状态：已确认（已实施）
- 日期：2026-10-21

**原方案**
`README.md` 同时承担简介、使用说明、设计理由、调参指南、未完成清单；交接靠 `MERGE_NOTES.md` 式的长文，每轮重写一份。

**现方案**
按职责拆成 README / AGENTS / PRODUCT / STATUS / DECISIONS / VALIDATION / data README 七份。每条产品规则有稳定编号（`CHAT-*`、`WORLD-*`、`SCOPE-*`），产品状态与实现状态分处两个文件。

**为什么改**
换一个 AI 或人接手时，最大风险不是不知道做过什么，而是**把讨论成果误认为已经上线**。原 README 里「≤15 字」既是规则又是实现描述，一旦方向变了，读者无法判断哪句还作数。

**影响面**
全部文档。`MERGE_NOTES.md` 移入 `docs/history/` 归档；根目录 `PLAN.md` **保持为持续维护的迁移计划**，与 README 是分工关系（README 说「现在能跑什么」，PLAN 说「要迁到哪、怎么迁」），不互相取代。

## DEC-005 · 括号互动取代「屏幕上只有字」

- 状态：已确认（代码未实现，见 [STATUS.md](STATUS.md) CHAT-007）
- 日期：2026-10-21

**原方案**
`TERMINAL_PROMPT` 写死「不要描述动作、表情、语气、环境。屏幕上只有字。」

**现方案**
`（）` 承载动作、表情与少量情绪；正文承载台词。允许纯动作回复，也允许完全无动作。

**为什么改**
纯文字终端能表达的内容太窄，长时间相处会变得单调——她无法「合上书」「把眼镜摘下来」，只能一直说话。而话少恰恰意味着很多时候她**不该说话**，却只能沉默地回一个「……」。

**影响面**
- `prompt_builder.py::TERMINAL_PROMPT` 第 4 条
- `README.md`「屏幕上只有字」段
- `check_persona.py`：新增模板词重复检测
- 打字机逐字输出**不改**（括号内容照常逐字打出，这是期望行为）
- 括号内仍禁止感叹号，与 [PRODUCT.md](PRODUCT.md) CHAT-005 一致

## DEC-006 · 规则改动必须五处同步

- 状态：已确认（长期约束）
- 日期：2026-10-21

**背景**
`web/index.html::checkReply()` 与 `scripts/check_persona.py::simulate_check_reply()` 是同一套角色规则的两次独立实现，`scripts/test_frontend.js` 第 136–150 行会把两边逐例比对。只改一边，回归立刻变红——但红的原因会被误读成「新规则不对」。

**约定**
改角色表达规则时，按以下顺序一次性改完：
1. `personas/*.json`（`system_prompt`、`examples`、`guard`）
2. `prompt_builder.py`（`TERMINAL_PROMPT`、`WORLD_PROMPT`）
3. `web/index.html::checkReply()`
4. `scripts/check_persona.py::simulate_check_reply()`
5. `scripts/test_frontend.js` / `scripts/test_backend.py` 中锁住旧行为的断言

**为什么写进决策**
这是最容易踩且最容易被误解为「测试有问题」的坑。第 5 条尤其重要：测试有时是**故意**锁住当前行为的（如 `test_05`），改行为时必须显式重写它，而不是删掉。

## DEC-007 · 不把自然表达做成配额指标

- 状态：已确认（长期约束）
- 日期：2026-10-21

**背景**
第 1 版计划为了「防止跑偏」，加了一批可量化规则：连续两轮结巴算过载、十轮里必须有几次无动作/几次纯动作、同一动作出现两次就报错、主线示例维持十字左右、把「面无表情」「脸颊泛红」列入禁用模板表。

**现方案**
以上全部撤销或降级：

| 撤销的写法 | 现在怎么处理 |
|---|---|
| 连续两轮结巴 = 过载 | 人工观察是否脱离情境 |
| 十轮含 N 次无动作、N 次纯动作 | 不做轮次统计 |
| 同一动作出现两次即报错 | 至多在调试面板提示，不判错 |
| 示例平均字数指标 | 不设指标，示例长短不齐 |
| 禁用模板词表 | 「面无表情」「脸颊泛红」是**允许**的描写 |

**为什么改**
这些规则会把「自然」变成完成指标：模型为了满足配额而安排动作和停顿，结果**更**机械。字数上限的教训已经证明过一次——用可量化的代理指标替代真实判断，最后代理指标本身变成目标。角色表现只能靠人读对话来判断。

**影响面**
- `check_persona.py`：不加配额类断言
- `docs/VALIDATION.md`：`V-FORM-01`、`V-CHAT-04` 改为人工观察
- `docs/PRODUCT.md`：CHAT-004、CHAT-007 的措辞

## DEC-008 · 世界归属审计以证据为准，不预判切点

- 状态：已确认
- 日期：2026-10-21

**原方案（第 1 版计划）**
把片尾 `2:41:10` 起的 5 条对白「疑似已回到原世界」当作待确认结论；并拿「崩溃世界问『你为什么戴眼镜』命中 `0:35:57`，该条属 normal」来证明切分规则正确。

**现方案**
- 时间空档只是**提示需要检查**，不构成归属证据。
- `0:35:57` 的 normal 标签来自**旧切分规则本身**，只能说明「旧规则与展示一致」，**不能**用来证明规则正确——这是循环论证。
- 审计产出证据表（片段 / 上下文 / 依据 / 待确认），证据不足标 `unknown`；需要用户裁定的片段单独列出，附上下文。

**为什么改**
用旧规则的产物去验证旧规则，永远会通过。审计的价值在于**独立于现有标签**重新建立依据。

**影响面**
- `PLAN.md` §6.4
- `docs/VALIDATION.md` `V-WORLD-04`、§五的更正说明
- `docs/STATUS.md` BLK-001 的表述

## DEC-009 · 可选后端：复用本机 Qoder 连接器

- 状态：已确认（已实现）
- 日期：2026-10-21

**背景**
项目原本只支持「用户自带 API Key」。本机装有 `dsh-qoder-connect` 插件，已登录且额度可用，但它的接口没有对外暴露：插件自带一个 loopback shim（`src/shim.ts`），端口随机、Bearer 每进程随机、两者都只活在 DSH 进程内存里，不落盘。外部程序发现不了它。

**现方案**
`qoder_backend.mjs` 用**插件自己的导出**（`QoderCredentialStore` / `QoderUpstreamClient` / `createQoderShim`）另起一个已知地址的端点，把地址与本地 token 写进 `~/.dsh/qoder-backend/state.json`。
`server.py` 的 `/api/backends` 读这个文件，并**真的连一次 `/v1/models`** 确认端口还活着（文件存在 ≠ 进程存在）。

**为什么不是「把 PAT 复制出来直连 Qoder」**
那需要重新实现 Qoder 的请求签名与 WASM 编码，且会把长期凭证暴露给项目。走插件自己的代码路径，签名和凭证管理都留在原处。

**前端只传 backend id**：地址与 token 由服务端解析，不接受前端指定，避免这个接口被指向任意地址。

**为什么留在库里**
它和插件一样，是挂在核心外的外挂件：**项目本身不依赖它**，没装插件、没有账号，走自己的 API Key 照样能用。留着是因为真实试聊每次都要跑，删掉等于每轮重写一次。
所以文档里不把它写成「正式功能」——没有正式/临时的分别，就是「能接上就接上」。

**已知脆弱点**
依赖插件内部构建产物：`lib/variants-*.js` 里 `createQoderTransport` 的导出名是压缩后的单字母，所以按**函数名**查找而不是按别名。插件升级或改打包方式后可能失效。**失效时必须明确报错**，不静默降级成「看起来能用但答不出来」。

**影响面**
- 新增 `qoder_backend.mjs`、`scripts/live_chat.py`
- `server.py`：`/api/backends` 路由、`api_chat` 的 backend 分支
- `web/index.html`：设置面板的后端下拉、`/api/backends` 加载
- `scripts/test_backend.py`：`test_10`、`test_11`
